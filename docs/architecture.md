# 技术架构

## 基本原则

- **个人、轻量**：只给我一个人在一台 Mac 上用，不做账号、协作、云端、跨平台。
- **够用就好**：能用简单办法的，不用复杂办法。
- **数据能长期保存、随时带走**：App 随时可以换掉，数据不丢。
- **默认离线**：联网的只有小拾的云端模型、插件库和「添加网页」。

## 技术选型

| 部分 | 选择 |
|---|---|
| 桌面应用 | Tauri 2 |
| 界面 | React + TypeScript + Vite，Tailwind CSS；少量自己写的组件，不用组件库 |
| 数据层 | Rust + SQLite |
| 小拾（AI） | Rust 用 reqwest 连模型、收流式回复；消息排版用 markdown-it、highlight.js、KaTeX |
| 读写文件 | PDF 用 PDFKit、读 Word 用 `textutil`、缩图片用 `sips`（都是 macOS 自带）；PowerPoint 和改 Word、写 Word 用 `zip` + `quick-xml`，表格用 `calamine`，网页正文用 `dom_smoothie` |
| 辅助脚本 | TypeScript（Node），不用 Python |

## 分层

```
界面（React） ──┐
               ├── 调用命令 ──▶ Rust 命令层 ──▶ SQLite（pomelo.db · picky.db · search.db）
小拾的 Agent ───┘              业务规则、校验都在这里
                               │
                               └─ 小拾服务 ──▶ 本地模型 8080 · 向量 8081 · 重排 8082 · 五家云端
```

- 只有 Rust 读写数据库，界面只调用 `books_list` 这样的命令。
- 小拾的工具也是 Rust 命令（只读查询、「提议」），AI 碰不到数据库；启停模型、芝麻开门、导入导出、备份恢复、写文件永远不做成工具。
- 用模型都经过「小拾服务」：聊天、定时任务、简报、润色补全、翻译都一样。本机其他程序要用本地模型，照旧直接连 8080。

## 数据存放在哪里

| 位置 | 放什么 | 备份 |
|---|---|---|
| `/Applications/Pomelo OS.app` | App 本体 | 不用 |
| `~/Library/Application Support/Pomelo OS/` | 真实数据：`pomelo.db`（生活数据和设置）、`picky.db`（小拾）、`backups/` | **要** |
| 同上的 `attachments/` | 笔记、任务、目标的附件（原文件的副本） | 不进每日备份，交给 Time Machine 这类工具 |
| 同上的 `picky-files/` | 小拾的附件和项目资料（原文件的副本，和上一行各存各的） | 不备份，也不需要另外备份（你定的） |
| 同上的 `search.db` | 搜索索引：从数据算出来的分段和向量、知识库文件夹的清单 | 不备份、不导出，删了自动重建 |
| `~/Library/Application Support/Pomelo OS Dev/` | 开发用的测试数据 | 不用 |
| macOS 钥匙串 | 芝麻开门 Touch ID 用的钥匙；云端 Key、插件库的 Key | 不进备份 |
| `~/Documents/LLM` | 本地模型、模型清单、启停脚本 | 独立的文件夹，由 Claude 维护；Pomelo 只读清单、调脚本 |

不要把数据库放进 iCloud、Dropbox 等同步文件夹，同步可能把它弄坏；想异地保存，就复制**备份文件**。

## 开发版和正式版

- 同一份代码，区别只在数据目录：正式版是「应用程序」里的 App（真实数据），开发版直接从代码运行（测试数据，随便清空）。阶段验收后 `pnpm app:install` 更新正式版，新版第一次打开时先自动备份再升级。「应用程序」里只应该有一个 Pomelo OS。
- **签名**：用固定的自签名证书「Pomelo Self-Signed」，系统认得每次更新的是同一个 App，钥匙串里的 Key 更新后还能读。但每次更新后第一次读 Key 还会弹一次「是否允许」：自签名证书没有团队编号，钥匙串只能按每个版本认。要不弹得换苹果开发者证书，你选了保持现状。
- **开发版和测试里的小拾只用模拟的**：模拟的模型清单、启停和回复，Key 只在内存；不启停我的模型、不连真实接口、不碰钥匙串。只有正式数据目录的打包版连真实的；开发版要接真模型用 `POMELO_REAL_MODELS=1 pnpm app:dev`（先问我）。云端模型我在正式版里自己测。

## 数据库升级

- 每次改结构都新增一个编号脚本（`src-tauri/migrations/`），用过的永远不改。`picky.db` 有自己的一串脚本和版本号。
- App 启动时需要升级：**先自动备份**，再逐个执行。数据库比 App 新（比如装回了旧版）时拒绝打开。
- `search.db` 只有版本号、不升级：对不上就删了重建。

## 备份与导入导出

| | 快照备份 | 数据文件（JSON） |
|---|---|---|
| 是什么 | 整个数据库的副本，在 `backups/` 里 | 所有模块的数据，人能看懂 |
| 用途 | 出问题时恢复 | 长期归档、换工具、从 Excel 导入 |
| 什么时候做 | 每天第一次打开、升级前、覆盖导入前、恢复前自动做；也能「立即备份」 | 「设置 → 导出…」 |
| 怎么用回来 | 设置里的备份列表，「恢复」 | 设置里「导入」 |

- **每日备份**：`pomelo.db` 留最近 30 份，`picky.db` 留最近 7 份，更早的每个月只留最后一份；两个库分开显示、分开恢复。其他备份不自动删。
- **恢复**把当前数据整个换成那份备份（先备份当前的）；老版本的备份恢复后自动升级，损坏的或比 App 新的拒绝。
- **导入**时文件里只要有一条不合格就一条都不导入；覆盖前先确认并备份。
- 文件名写着时间和原因：`pomelo-20260929-093000-daily.db`、`manual`、`before-v7`（升级到版本 7 前）、`before-import`、`before-restore`；小拾的以 `picky-` 开头。

## 附件

- **存**：Rust 把文件复制到 `attachments/`（随机名、只有你的账户能读写），同样的内容（按 SHA-256）只存一份；界面只拿到编号、名字、大小。
- **看**：图片通过 `pomelo-file://localhost/<编号>` 显示，Rust 只按编号给已经存下的图片；其他文件交给 macOS 用默认程序打开。
- **拖进来、粘贴**：交给落点所在的那一块（正在写的笔记、打开的任务面板、目标对话框；都不是就给最近打开的那块）。粘贴的截图没有路径，界面把内容直接交给 Rust 存。
- **删**：删记录不删副本（这样能撤销），没人用的在「设置 → 数据 → 附件」里清理。

## 芝麻开门的安全

- **加密**：设主密码时随机生成一把「密码库钥匙」，每条密码和每个分类名都用它加密（XChaCha20-Poly1305）后才写进数据库；明文的只有顺序、分类编号、归档这几个数字。主密码经过 Argon2id（256 MB、3 轮，约 0.3 秒）算出另一把钥匙，把密码库钥匙锁起来存着。主密码本身哪里都不存。
- **打开**：输主密码，或用 Touch ID 从钥匙串取出密码库钥匙；规则（3 次失败、3 天、更新后）都在 Rust 里判断。打开后钥匙只在内存里，5 分钟没用就清掉（按真实时间算，睡眠也算）。
- **谁读得到**：数据库、备份、导出文件里都没有明文，任何读文件的程序（包括 AI 编程助手）只看到乱码。钥匙串里那份，别的程序要读系统会弹窗要登录密码。复制密码由 Rust 放进剪贴板（标成「隐藏」，剪贴板工具不记），30 秒后清掉；列表里从不带密码。
- **还剩的口子**：① 钥匙串里 Touch ID 那份只靠电脑登录密码挡着。② 拿到数据库或备份的人能离线一个个试主密码（每次约 0.3 秒），主密码越长越难。③ 复制后的 30 秒里别的程序读得到剪贴板；密码「显示」时能截屏的程序看得到。④ 正式版没开「强化运行时」，以你身份运行的恶意程序理论上能注入 App。能加固的（「只用主密码」开关、强化运行时），你选了保持现状。
- **代价**：主密码忘了就打不开，没有找回办法。

## 撤销

- 每个改数据的命令执行时，用 SQLite 自带的「会话」功能记下改了哪些行（连同一起删掉的子项）；⌘Z 反着应用一遍，⌘⇧Z 再正着应用。`pomelo.db` 和 `picky.db` 分开记。
- 最多 100 步，只在内存里。设置（比如侧栏顺序）不算；发消息、生成回复、建索引、删副本、后台自己跑的（例行检查、定时任务、简报）不算，可撤销的编辑也不碰它们记的东西，免得 ⌘Z 被挡住。
- 数据在这之间被改过、对不上了，就拒绝撤销并清空记录，不会写坏数据。导入和恢复备份也清空记录。

## 拖拽排序

界面拖完后把这几条的新顺序交给 Rust。可以只是一组里的一部分（比如没做完的任务、筛选后的课节）：它们在自己原来的位置之间互换，看不到的条目不动。Rust 检查这些条目确实属于这一组，再重写 `sort_order`。拖拽用鼠标事件自己做（macOS 的网页控件对原生拖放支持不好）。

## 打开链接

带协议的（`https:`、`mailto:`、`bear:` 等）直接交给系统；`/…`、`~/…` 当作本机文件；其他的（比如 `www.xx.com`）补上 `https://`。

## 模块之间

一个操作要改好几张表时放在一个事务里（可以嵌套，模块互相调用、导入时调用各模块都不冲突），中途出错就全部不算。

- **五花八门、循序渐进**：建出来的每一个当一个模块，键是 `list/编号` 或 `progress/编号`（也是页面地址）；侧栏顺序、隐藏、「发给云端」、循序渐进的类型列表（`kinds` 表里 `module` 就是这个键，和随意画画的类型同一套）都按键存，所以编号永远不重用。单选、多选的选项和循序渐进的类型按在列表里的位置配颜色（`--tag-1`～`--tag-8`，超过 8 个从头再来），只是显示，不存。界面的模块列表 = 固定模块 + 从 Rust 读到的建出来的模块。五花八门每条的字段值存成一份 JSON，规则都在 `lists.rs` 里检查；排序、筛选只是页面上的显示。小拾用两个工具（`pomelo_lists`、`pomelo_progress`）查它们，工具说明里不写模块名（不带个人数据）。
- **笔记转待办**：任务记下来自哪条笔记（笔记删了变空）；数据文件里用笔记的记录时间对上，导入时先导笔记再导待办。小拾「拆成待办」和「拆成子任务」一样：模型只列出来，勾选后一步加上。

## 搜索和索引

- **全局搜索**（按字）：Rust 在 SQLite 里逐条比对每个模块要搜的字段（中英文都能找到词中间的字），每个词都出现才算，每类最多 6 条。界面跳到那个模块，由模块页面打开那条记录（`src/shared/open.ts`）。
- **一个入口**：`search/query.rs`，「意思相近」和小拾的搜索都调它。给它一句话、范围和方式（按字、按意思、合并），返回记录在哪、标题、片段、得分和怎么找到的。芝麻开门不进索引；隐藏的模块、云端规则在这里挡。向量或重排服务用不了时照样按字返回。
- **三种方式**：按字用 FTS5（中文两个字一组）；按意思把问题和记录都算成向量比相似度；合并是两种名次合在一起，再用重排模型给前 30 条打分：有把握的（0.1 分以上）排前面，其余保持合并后的顺序（「找房子」这种短词它对什么都给接近 0 分，全按它排会把对的挤下去）。
- **索引和原始数据分开**：`search.db` 只放算出来的东西（每条记录要搜的文字、指纹、全文索引和向量，项目资料、记忆、知识库的分段和向量）；「哪些要建索引」这类选择留在 `picky.db`。
- **后台更新**（`search/indexer.rs`）：用自己的只读连接，每 2 秒看一眼两个数据库有没有被改过（SQLite 的 `data_version`，撤销、导入、恢复都算），有就按指纹比对，只写变了的、删掉没了的。不用在每个命令里挂钩子。
- **向量什么时候算**：只在向量服务本来开着、或按意思搜 / 小拾检索要用时补算，不为改一条记录专门启动服务。重建（`search.db` 新建、换向量模型、换文字规则）例外：自动启动服务，在后台从新到旧算完，期间照常按字找。
- **速度**：向量压成 8 位整数载入内存逐条比（20 万段约 200 MB）；20 万条实测按字约 0.06 秒、按意思约 0.02 秒。再大就换近似检索，所以向量检索做成了能换的部件。
- **全量读取**：年度总结这类要看全部数据的任务不经过检索，直接用各模块的只读函数读全。

## 首页和每天的例行检查

- **首页**：数字和清单由 `home.rs` 每次打开时现算（只读，不存东西），隐藏的模块不算；今天的待办直接用一步一步的列表。
- **例行检查**：每天第一次打开 App、或开着过了零点，做三件事：每日备份；把时间段结束或已经打满的打卡任务标为完成；记上到日子的固定支出（漏掉的一起补）。窗口关着、只留菜单栏时，每日备份每 5 分钟检查一次，另外两件等下次打开窗口补上。这些不进撤销（撤销了下次还会再做）。

## 图表

回看、钱来钱往和首页的图表是自己用 SVG 画的（柱状图、折线、圆环、排行条、预算条），不引入图表库。颜色是一套检查过色弱可读性的固定顺序，深浅模式各一套；每张图旁边都有对应的数字或清单。

## 占用空间和内存

App 本体约 7 MB，运行内存约 85 MB；导入全部现有数据后 `pomelo.db` 约 0.5 MB，十年也在几百 MB 以内。真正占空间的是附件。

## 小拾（AI）

- **同时生成**（`chat.rs` 的 `Runs`）：每个对话一个生成位置（回复或总结），不同的对话、定时任务、助手、简报各写各的；状态里列出每个正在写的（对话、模型、读到哪、排没排队），页面和小窗只看自己这个对话的。本地服务一次只答一个请求（`llmctl.sh` 开 `--parallel 1`，上下文整个给它）：所有发给本地模型的请求在 `provider.rs` 里排队（`local_turn`），排着的回复收到「排队中」，轮到了再发；云端不排队。云端请求在还没收到任何内容时遇到 429、5xx、流里的错误（OpenRouter 把上游的状态码放在 `error.code`）或连接失败，等 2 / 5 / 10 秒（有 `Retry-After` 就照它，最多 20 秒）再发，最多 3 次，等的时候也发「排队中」（页面按云端写「云端模型忙」）；OpenRouter 的 429 重试完还不行，报它是上游共用额度的限流。正在用本地模型时不能停它、换别的本地模型，别的随时能换（写着的回复用的是开始时定好的模型）。
- **小拾服务**：一个统一的「发消息、流式收回复」接口，背后是本地模型（8080，OpenAI 兼容）或五家云端（只连固定的官方 HTTPS 地址；Anthropic 用它自己的 Messages 接口，其余是 OpenAI 那种接口）。回复、思考过程、用量一边收一边交给界面，定时存进 `picky.db`；中断时保存已收到的。出错只显示固定的中文提示。
- **思考**：每次调用都说要不要思考，模型能不能做到看它的思考能力（云端在设置里标，本地照清单），只有「能开关」的模型收到开关（各家的写法在 `provider.rs`）；要思考的多留回复长度。关不掉思考的模型拒绝「关」时去掉设置再发一次，并记住到退出。一次回复里查数据的那几轮，各家要求发回的思考内容（OpenRouter 的 `reasoning_details`、Google 的思考签名、Anthropic 带签名的思考块）原样发回；以前的问答只发文字。
- **本地模型**：读 `~/Documents/LLM/config/models.json`（聊天、向量、重排三类），用 `llmctl.sh` 启动、切换、停止，查 `/health` 判断状态。聊天模型同一时间一个（8080）；向量（8081）、重排（8082）用清单里各自的第一个，要用时自动启动。小拾启动的（脚本记着）闲置 30 分钟后停、退出柚儿园时停；别处启动的不碰。聊天模型的上下文按名字里的大小限制（14B 及看不出的 16K，更小的 32K；清单、`llmctl.sh`、Pomelo 三处都拦）。这些控制只给界面和菜单栏，不交给 AI。
- **数据**：`picky.db` 存对话、消息版本树、调用记录、附件和分段文字、模板、预设、摘要、记忆、项目资料、出处、卡片、定时任务、简报、知识库的选择（表见[数据结构](schema.md)）；分段和向量在 `search.db`；文件副本在 `picky-files/`。
- **追问时的附件**：同一条路径上前面问题的附件仍随新问题发出，但标成「前面附过」，在问题里另起一段（分段阅读时写在要点后面），和这一问新附上的分开（`reading.rs`）。
- **读文件**（`files.rs`、`office.rs`）：添加时读一次存成分段文字。PowerPoint 读每页幻灯片 XML 里的字；表格用 `calamine`，CSV 自己解析；网页在 Rust 里下载（20 秒、5 MB 以内），取正文成 Markdown，开发版存模拟网页。大表格只存表头和前 50 行，「查表」每次从副本现读整张表再筛。图片不存文字；发给云端前在临时文件夹里用 `sips` 缩小，按各家的格式放进问题；本地模型只收到一句「看不了图片」。
- **挑选和检索**：记忆和资料段落先按向量相似度取一批（记忆 12 条、资料 20 段，0.30 以上），再用重排模型挑出至多 6 条；重排用不了就只按相似度（0.35 以上）。知识库同样。
- **出处**（`cite.rs`）：一次回复拿到的东西编号：检索到的段落在问题里写成「【[1] 资料名 · 第 3 页】」，「搜索」工具返回「[2] 笔记 · 2026/09/13：片段」，同一条记录一个号；私密对话不在结果里。编号随回复存进 `picky.db`，界面把 [n] 变成能点的小数字。「读整条」读之前再按能读和云端的规则查一遍。
- **查数据**（`data.rs`）：用模型的工具调用。Rust 定义每个模块的只读查询（合计和统计和页面共用一个函数），先检查能不能读、这次能不能发给云端，再查、截短后交回；一次回答最多 4 轮。查到的存进 `picky.db`，追问和回看都用得上。小窗只告诉 Rust 当前页面和记录编号，内容由 Rust 按同样的规则取。
- **改数据**（`act/`）：七个模块共 14 个写数据的工具，模型只能「提议」：Rust 读它给的字段（日期词按今天算、名称对上已有的），要改的那条由 Rust 按名称里的字去找（几条就都列出来让我选）。每个候选用模块自己的函数在一个最后撤回的事务里试写一遍，前后一比就是卡片上的「改前 → 改后」，过了才放进卡片。告诉模型的话照抄卡片，它才不会说错。查数据的 4 轮之后还有一轮只给写数据的工具。确认时界面只传卡片和勾了哪几条，Rust 按卡片里存的写入，整张一步 ⌘Z。隐藏的模块不给工具；云端不允许的模块工具照给但一律拒绝。
- **润色、补全、一句话填好**（`assist.rs`）：一问一答、开思考；Rust 写好提示（一句话填好附上今天前后的日历和已有的分类、分组、渠道、模板），把回答读成字段再检查一遍才交给面板；保存照常走各模块的命令。
- **插件库**（`skills/`）：技能是 Rust 写好的固定功能。开着、Key 齐了、并且「自己决定用」或这一条点名要它，才给模型这个工具；点名要的在系统消息里写明必须先用它；点名联网的，Rust 先拿问题本身（前 300 字）搜一次再交给模型。不用 `tool_choice: required`（有的服务不认）。查到的都编号成出处、记进「查了」。
  - **联网**（`web.rs`）：调 Tavily 的固定地址，Key 只在钥匙串。
  - **书单 / 影单检索**（`works.rs`）：先用 Wikidata 找到这一部（认得中文名和译名，带着类型、作者 / 导演、国家和各家的编号），再按编号去 Open Library、TMDb、Jikan 核对；Wikidata 找不到才用各家自己的搜索，并写明没交叉核对。Wikidata 排队、每次隔 0.35 秒，被限速等 3 秒再试，请求头带插件库里的联系邮箱（存在 `picky.db` 偏好里，不写进代码）；查到的在内存里留 6 小时。
  - **读文件**（`files.rs`）、**查知识库**（`knowledge.rs`）：由 `chat.rs` 执行（要用到这个问题的文件、对话的知识库），只在有东西可读时给。资料放不下时，开着「读文件」就不再分段阅读：发每个文件的目录（「第 3 段 · 小标题：开头几个字」，不用方括号，免得和出处混）和按问题挑出的段落（问题里的两字词和英文词，越少见权重越高；最多 8 段、每段至少最高分的一半、截到 1500 字左右，每个文件至少给第一段），放不下就减半再试；读到的段落和挑出的一样编号成出处。
- **定时**（`schedule.rs`）：后台循环每 30 秒（打开后 5 秒第一次）看有没有到点的任务。跑的时候和发消息走同一条路，只是没有界面在听、只读（不给写数据的工具）、系统消息说明我不在。要用的本地模型没运行就先启动，跑完只停它自己启动的。「上次跑到哪」放在单独的表里，不进撤销。页面看状态里「正在写的回复」变了，就重新读那个对话。
- **今日简报**（`brief.rs`）：Rust 先用 `data.rs` 读好待办、该提醒的日子、投递、最近两周的笔记（每块有上限），一次请求，最多等 5 分钟（云端只回心跳时 15 分钟后才报错）。不占对话的那个生成位置，和对话、定时任务能同时跑；谁启动的本地模型谁停。
- **年度总结**（`yearly.rs`）：不用查数据的工具，Rust 先读好全部（每月的笔记、做完的事、画完的课、投递、对话；全年的书影、课程、打卡、出行；算好的数字、去年同期的数字和差值、去年的年度总结）。估算放得下（云端留它的回复上限、最多 32K，本地留三分之一）就一次发；放不下就按月整理要点（云端同时 4 个月、本地一个一个来，存进 `month_summaries` 并记下读的内容的指纹，下次一样就直接用；一个月放不下就分段读），再拿要点写全年，还放不下就先去掉去年的那篇。思考照任务的设置。写的是哪一年记在 `year_runs`，首页卡片和明年的比较都找它。
- **知识库的文件和整篇读**（`knowledge.rs` 的 `kb_tool`）：「查知识库」按 `view` 分：search 照旧检索；files 列 `search.db` 里扫描到的文件（按路径里的字筛，放不下就截断并说还有几个）；outline / read / find 先按路径（或文件名）认出是哪个文件，再从原来的文件夹现读（网页读副本），和「读文件」用同一套目录、按段读、按字找（`skills/files.rs` 的 `read_view`、`find_view`），读到的段落编号成知识库的出处。look 看一张图片（只给云端模型）：Rust 从文件夹现读、同附件一样缩小（`office::image_for_model`），编号成出处，图片在这一轮的结果之后另起一条 user 消息发（工具结果只能是文字；Anthropic 和结果放在同一轮），一个回答最多 8 张。图片扫描时进 `kb_docs`（按扩展名认），`PENDING` 把它们排除，不建索引、不算待更新，管理里单独数。路径照旧检查不出文件夹，云端规则照 `scope`。
- **知识库**（`knowledge.rs`）：`picky.db` 只记库、文件夹（完整路径）和网页（正文副本）、云端开关、对话和项目选的库，这些都能撤销。文件夹里有什么、分段和向量放在 `search.db`（`kb_docs`、`kb_chunks`）：后台扫描只写 `search.db`，不挡 ⌘Z，删了就重扫重算。不监听文件：打开小拾页、打开知识库对话框、菜单栏的后台循环每 10 分钟比大小和修改时间。建索引一次一个，读文件、切段和附件同一套，文字没变的段落沿用旧向量。向量服务本来开着就在后台建，没开着就等提问：发送前 Rust 先把这次要查的库里待更新的算完（这时启动服务），再检索、重排。哪些库、能不能发给云端都在 Rust 判断，界面只传对话编号或草稿的开关和选的库。「打开文件」由 Rust 检查路径没出文件夹再交给系统。
- **助手**（`assistants/`）：各有自己的页面，不占对话。设置和上一次的结果放在 `picky.db` 偏好（`assistant.<名字>`），不进撤销和导出。**翻译**（`translate.rs`）：模型照定时任务的规则选（本地没运行就启动，翻完不停）；提示词由 Rust 拼（语言方向、四组关键词、自己写的一段）。长文按换行、句子切块（标题跟着它下面的正文，不留在块尾），每块留两倍长度给译文（开思考再加），依次流式翻；后一块带上前一块译文的结尾（300 字以内）和最后一个标题，只用来对齐译法和编号，并写明要从第一句完整翻。翻译在后台任务里跑，结果先放内存、每秒存一次，页面每 0.3 秒问一次，所以离开、刷新都不丢；停止就是取消任务。不占对话的生成位置。
- **Work**（`work.rs`、`word.rs`、`skills/toolbox.rs`）：「保存为 Word」把回答的 Markdown 转成自己写的 .docx（真正的标题、列表、表格、引用、代码样式，苹方；出处列在文末），只在你点了以后、在你选的文件夹里新建，不覆盖。改文件是插件库的两个技能：Word 工具箱（`pomelo_word`：files、read、edit、create）和文本工具箱（`pomelo_text`：files、read、edit），和查数据一样在对话的工具循环里用，定时任务不给（`Skill::writes`）；最后那一轮（只能提议的）也给工具箱。能改的文件由 Rust 列出（也写进系统消息，不用先 files）：附件的原文件（加附件时记在 `artifacts.source_path`）、旧问题选的文件、知识库文件夹里的文件，别的路径一概不认。read 把文件分成段落编号（Markdown / 纯文本按空行，Word 读 `word/document.xml` 的正文段落和表格），末尾提醒「还没改，要改就 edit」；edit 每段先检查，过了就放进这条回复的卡片（`file_edits`，一条回复一个文件，记下第一次提议时文件的指纹），回给模型的写明哪段删掉、哪段后面加了几段；create 把文件名和 Markdown 放进卡片（`kind = new-word`）。「写入文件」时先比指纹，变了就不写；再在同一个文件夹写新文件、改名盖过去（保留权限）。新建的 Word 在你点「保存」时写进你选的文件夹（同「保存为 Word」）。Word：给模型看的段落带格式标记（段首 # 标题、- / 1. 列表，**加粗**、*斜体*、<u>下划线</u>，只看文字块自己的格式），改回来时新旧文字按字比（最长公共子序列），只改 `w:t` 里变了的字，新加的字放进旁边格式对得上的那个文字块；某一段文字的加粗、斜体、下划线变了，才把那个文字块拆开（别的属性照抄，属性按规范的顺序排）；标题照 `styles.xml` 里叫「heading N」的样式，列表照附近同类列表段落的 `numPr`（列表的种类看 `numbering.xml`）。空一行是在后面加新段落（照抄这段的段落属性，去掉分节），空的是删掉整段（有书签、批注、图片、分节的不删）。表格一行一行给（「| 格 | 格 |」），改回来时行数、每行格数要一样，变了的格子按上面同样的办法改（格子只有一段才行；空格子加一个文字块，用段落标记的格式）；表格里套表格、格子里有 | / 制表符 / 换行的整张不能改，好几段的、和上面合并的格子不能改。其余 XML 一个字节都不动；碰到段内制表符、换行的改动不收。参考资料截到窗口的三分之一跟着发。
- **云端 Key**：只在钥匙串（和插件库的 Key 同一组），界面只显示「已保存」；不进数据库、备份、导出和日志。
- **空间管理**：算数据库和 `picky-files/` 的大小，列出每份副本被谁用着；删副本只删文件、留下记录（「文件已删除」）。
- **开机自动启动**（`autostart.rs`）：Tauri 的 autostart 插件写一个带 `--hidden` 的 LaunchAgent，不用 AppleScript。带 `--hidden` 打开时，窗口第一次画出来之前就藏起来。开关存在设置里（默认开），每次打开时让登录项跟着开关；只有正式数据目录的打包版会登记。
- **Pub2MD** 以后作为助手并入（也用小拾服务连模型）；**Seeker**（简历和面试材料）保持独立，Pomelo 只记里面文件的位置。
