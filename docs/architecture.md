# 技术架构

## 基本原则

- **个人、轻量**：只给我一个人在一台 Mac 上用，不做账号、协作、云端、跨平台。
- **够用就好**：能用简单办法的，不用复杂办法。
- **数据能长期保存、随时带走**：App 随时可以换掉，数据不丢。
- **默认离线**：联网的只有小拾的云端模型、插件库、「添加网页」、Pub2MD（Mathpix）和呦呦漫游的发布。

## 技术选型

| 部分 | 选择 |
|---|---|
| 桌面应用 | Tauri 2 |
| 界面 | React + TypeScript + Vite，Tailwind CSS；少量自己写的组件，不用组件库 |
| 数据层 | Rust + SQLite |
| 小拾（AI） | Rust 用 reqwest 连模型、收流式回复；消息排版用 markdown-it、highlight.js、KaTeX |
| 读写文件 | PDF 用 PDFKit、读 Word 用 `textutil`、缩图片用 `sips`（都是 macOS 自带）；PowerPoint 和改 Word、写 Word 用 `zip` + `quick-xml`，表格用 `calamine`，网页正文用 `dom_smoothie` |
| 辅助脚本 | TypeScript（Node），不用 Python |

## 分层

```
界面（React） ──┐
               ├── 调用命令 ──▶ Rust 命令层 ──▶ SQLite（pomelo.db · picky.db · search.db）
小拾的 Agent ───┘              业务规则、校验都在这里
                               │
                               └─ 小拾服务 ──▶ 本地模型 8080 · 向量 8081 · 重排 8082 · 五家云端
```

- 只有 Rust 读写数据库，界面只调用 `books_list` 这样的命令。
- 小拾的工具也是 Rust 命令（只读查询、「提议」），AI 碰不到数据库；启停模型、芝麻开门、导入导出、备份恢复、写文件永远不做成工具。
- 用模型都经过「小拾服务」：聊天、定时任务、简报、润色补全、翻译都一样。本机其他程序要用本地模型，照旧直接连 8080。

## 数据存放在哪里

| 位置 | 放什么 | 备份 |
|---|---|---|
| `/Applications/Pomelo OS.app` | App 本体 | 不用 |
| `~/Library/Application Support/Pomelo OS/` | 真实数据：`pomelo.db`（生活数据和设置）、`picky.db`（小拾）、`backups/` | **要** |
| 同上的 `attachments/` | 笔记、任务、目标的附件（原文件的副本） | 不进每日备份，交给 Time Machine 这类工具 |
| 同上的 `picky-files/` | 小拾的附件和项目资料（原文件的副本，和上一行各存各的） | 不备份，也不需要另外备份（你定的） |
| 同上的 `search.db` | 搜索索引：从数据算出来的分段和向量、知识库文件夹的清单 | 不备份、不导出，删了自动重建 |
| `~/Library/Application Support/Pomelo OS Dev/` | 开发用的测试数据 | 不用 |
| macOS 钥匙串 | 芝麻开门 Touch ID 用的钥匙；云端 Key、插件库的 Key | 不进备份 |
| `~/Documents/LLM` | 本地模型、模型清单、启停脚本 | 独立的文件夹，由 Claude 维护；Pomelo 只读清单、调脚本 |
| `~/Documents/GitHub/personal-website` | 个人网站（呦呦漫游编辑、发布的就是它） | 独立的项目，自己的 git 历史和 GitHub 仓库 |

不要把数据库放进 iCloud、Dropbox 等同步文件夹，同步可能把它弄坏；想异地保存，就复制**备份文件**。

## 开发版和正式版

- 同一份代码，区别只在数据目录：正式版是「应用程序」里的 App（真实数据），开发版直接从代码运行（测试数据，随便清空）。阶段验收后 `pnpm app:install` 更新正式版，新版第一次打开时先自动备份再升级。「应用程序」里只应该有一个 Pomelo OS。
- **签名**：用固定的自签名证书「Pomelo Self-Signed」，系统认得每次更新的是同一个 App，钥匙串里的 Key 更新后还能读。但每次更新后第一次读 Key 还会弹一次「是否允许」：自签名证书没有团队编号，钥匙串只能按每个版本认。要不弹得换苹果开发者证书，你选了保持现状。
- **开发版和测试里的小拾只用模拟的**：模拟的模型清单、启停和回复，Key 只在内存；不启停我的模型、不连真实接口、不碰钥匙串。只有正式数据目录的打包版连真实的；开发版要接真模型用 `POMELO_REAL_MODELS=1 pnpm app:dev`（先问我）。云端模型我在正式版里自己测。
- **编译缓存**：Rust 的编译结果（`src-tauri/target`）每换一次编译方式就多存一份，只增不减（曾经到过 70 GB）。开发编译时依赖不带调试信息、自己的代码只带行号，一次完整的编译测试约 3 GB；`pnpm check`、`app:dev`、`app:build`、`app:install` 和每次开 Claude Code 会话时，超过 20 GB 就整个清掉（`scripts/clean-build.sh`，下次编译从头编，约一分半）。

## 数据库升级

- 每次改结构都新增一个编号脚本（`src-tauri/migrations/`），用过的永远不改。`picky.db` 有自己的一串脚本和版本号。
- App 启动时需要升级：**先自动备份**，再逐个执行。数据库比 App 新（比如装回了旧版）时拒绝打开。
- `search.db` 只有版本号、不升级：对不上就删了重建。

## 备份与导入导出

| | 快照备份 | 数据文件（JSON） |
|---|---|---|
| 是什么 | 整个数据库的副本，在 `backups/` 里 | 所有模块的数据，人能看懂 |
| 用途 | 出问题时恢复 | 长期归档、换工具、从 Excel 导入 |
| 什么时候做 | 每天第一次打开、升级前、覆盖导入前、恢复前自动做；也能「立即备份」 | 「设置 → 导出…」 |
| 怎么用回来 | 设置里的备份列表，「恢复」 | 设置里「导入」 |

- **每日备份**：`pomelo.db` 留最近 30 份，`picky.db` 留最近 7 份，更早的每个月只留最后一份；两个库分开显示、分开恢复。升级前、导入前、恢复前的备份每种各留最近 3 份（每天做每日备份时清）；手动备份不自动删。
- **恢复**把当前数据整个换成那份备份（先备份当前的）；老版本的备份恢复后自动升级，损坏的或比 App 新的拒绝。
- **导入**时文件里只要有一条不合格就一条都不导入；覆盖前先确认并备份。
- 文件名写着时间和原因：`pomelo-20260929-093000-daily.db`、`manual`、`before-v7`（升级到版本 7 前）、`before-import`、`before-restore`；小拾的以 `picky-` 开头。

## 附件

- **存**：Rust 把文件复制到 `attachments/`（随机名、只有你的账户能读写），同样的内容（按 SHA-256）只存一份；界面只拿到编号、名字、大小。
- **看**：图片通过 `pomelo-file://localhost/<编号>` 显示，Rust 只按编号给已经存下的图片；其他文件交给 macOS 用默认程序打开。
- **拖进来、粘贴**：交给落点所在的那一块（正在写的笔记、打开的任务面板、目标对话框；都不是就给最近打开的那块）。粘贴的截图没有路径，界面把内容直接交给 Rust 存。
- **删**：删记录不删副本（这样能撤销），没人用的在「设置 → 数据 → 附件」里清理。

## 芝麻开门的安全

- **加密**：设主密码时随机生成一把「密码库钥匙」，每条密码和每个分类名都用它加密（XChaCha20-Poly1305）后才写进数据库；明文的只有顺序、分类编号、归档这几个数字。主密码经过 Argon2id（256 MB、3 轮，约 0.3 秒）算出另一把钥匙，把密码库钥匙锁起来存着。主密码本身哪里都不存。
- **打开**：输主密码，或用 Touch ID 从钥匙串取出密码库钥匙；规则（3 次失败、3 天、更新后）都在 Rust 里判断。打开后钥匙只在内存里，5 分钟没用就清掉（按真实时间算，睡眠也算）。
- **谁读得到**：数据库、备份、导出文件里都没有明文，任何读文件的程序（包括 AI 编程助手）只看到乱码。钥匙串里那份，别的程序要读系统会弹窗要登录密码。复制密码由 Rust 放进剪贴板（标成「隐藏」，剪贴板工具不记），30 秒后清掉；列表里从不带密码。
- **还剩的口子**：① 钥匙串里 Touch ID 那份只靠电脑登录密码挡着。② 拿到数据库或备份的人能离线一个个试主密码（每次约 0.3 秒），主密码越长越难。③ 复制后的 30 秒里别的程序读得到剪贴板；密码「显示」时能截屏的程序看得到。④ 正式版没开「强化运行时」，以你身份运行的恶意程序理论上能注入 App。能加固的（「只用主密码」开关、强化运行时），你选了保持现状。
- **代价**：主密码忘了就打不开，没有找回办法。

## 撤销

- 每个改数据的命令执行时，用 SQLite 自带的「会话」功能记下改了哪些行（连同一起删掉的子项）；⌘Z 反着应用一遍，⌘⇧Z 再正着应用。`pomelo.db` 和 `picky.db` 分开记。
- 最多 100 步，只在内存里。设置（比如导航顺序、模块坞的分类）不算；发消息、生成回复、建索引、删副本、后台自己跑的（例行检查、定时任务、简报）不算，可撤销的编辑也不碰它们记的东西，免得 ⌘Z 被挡住。
- 数据在这之间被改过、对不上了，就拒绝撤销并清空记录，不会写坏数据。导入和恢复备份也清空记录。

## 拖拽排序

界面拖完后把这几条的新顺序交给 Rust。可以只是一组里的一部分（比如没做完的任务、筛选后的课节）：它们在自己原来的位置之间互换，看不到的条目不动。Rust 检查这些条目确实属于这一组，再重写 `sort_order`。拖拽用鼠标事件自己做（macOS 的网页控件对原生拖放支持不好）。

## 界面外框

- **页签和前进后退**（`src/app/tabs.tsx`）：只在界面里：每个页签一串走过的页（最多 50 步），用路由地址记（`#/finance/assets`：模块的子页是地址的第二段，`subpage.ts`）。路由只显示当前页签的页，切页签就是换地址（页面重新打开）。索引签、模块坞、柚子瓣、全局搜索走 `open`（别的页签开着这个模块就切过去）；页面里自己的跳转照常，外框记下来。鼠标侧键用 `mouseup` 的第 4、5 键，也有 ⌘[ ⌘]。页签（各自当前那一页）存在 `settings` 的 `ui.tabs`，打开 App 时恢复。
- **模块坞**（`dock.ts`、`DockPage.tsx`）：分类和置顶存在 `settings` 的 `ui.dock`，按模块键记（建出来的是 `list/编号`、`progress/编号`），隐藏还用 `ui.module_hidden`（搜索和小拾也读它），都不进撤销。哪个分类都没有的模块（新加的、刚建的）放进它的默认分类。助手在导航里各是一个键（`translate`、`pub2md`、`seeker`），页面是小拾里原来的那几页，数据不动。柚子瓣（`Bloom.tsx`）是同一份设置的另一种画法（SVG），不另存；它一直挂着，编辑时只更新内容，不重新播展开的动画。拖动用鼠标事件（`drag.tsx`：落点用 `data-drop`、插在哪个前面用 `data-mod`，柚子瓣自己算落在哪一瓣）。实时小字是 Rust 的只读命令 `dock_live`（`dock.rs`）。
- **柚子**（`Pomelo.tsx`）：一个 SVG 组件，表情是参数，动画用 CSS（`frame.css`）。心情：今日简报（`brief.rs`）让模型在最后一行写「心情：…」，Rust 取出来存进 `briefs.mood`（正文不留），模拟模型给「很忙」（`?mock&mood=` 能换）；`picky_brief` 带上写好的时间（`moodAt`，就是那一行的 `updated_at`），界面只在这之后一小时内用它，其余时候每小时从不负面的几个里随机挑。状态：小拾在写读 `picky_status` 的 `generating`；出错由界面报（`reportProblem`）：每天的自动备份失败，发布和 Pub2MD 开始后登记一个检查（`watchJob`），外框每 2 秒问一次直到做完，离开那一页也照样报。
- **速记小窗**（`capture.rs`、`src/capture/`、`capture.html`）：同一个 App 的第二个窗口（`capture`），第一次按 ⌥Space 时才建，之后只是藏起来（每次重建要半秒多；藏着时页面也还在内存里，约几十 MB）。⌥Space 用 Tauri 官方的全局快捷键插件，只在运行时登记（开发版、测试版也会抢这个键；被占了就只能从菜单栏打开）。窗口浮在最上面、跨所有桌面、能盖在全屏 App 上（`FullScreenAuxiliary`）。呼出前记下最前面的 App，Esc / ⌘W / 关闭时还给它；点别处时页面收到 `capture-blur` 自己决定收不收（图钉、正在选文件时不收）。草稿是 `settings` 的 `capture.*`，页面随打随存（停 0.4 秒）、收起前再存一次；记下用自己的命令（建笔记或任务和清空草稿在同一个事务里，一步 ⌘Z），然后发 `capture-saved` 让主窗口刷新（在小窗里确认小拾的卡片也发，`picky_card_confirm` 看是哪个窗口调的）。问小拾（`CaptureChat.tsx`，第一次打开这一栏才加载小拾的 Markdown 那些）就是小拾自己的对话：`picky_send` 带 `capture`，新对话私密、记进 picky.db 偏好 `capture.chat`（同时只有一个，新的进来旧的删掉）；`library.rs` 的 `unlisted!()` 把它和 Rater 的复盘记录一起挡在对话列表、对话搜索、⌘K、索引和模块坞的对话数外面。「新对话」删掉它，「在 Pomelo 里继续对话」去掉偏好、取消私密，发 `capture-chat` 给主窗口去小拾页打开。回答里的记录链接在小窗的内存路由里被接住，发 `capture-open` 给主窗口照全局搜索的方式打开。有对话时 `capture_fit` 把窗口拉到 560 高（顶边不动，出了屏幕就往上挪），回去时还原。
- **Mac 菜单栏**（`menu.rs`）：自己建的菜单，代替 Tauri 默认的那份（默认的 ⌘W 是关窗口）。页签相关的菜单项发 `app-menu` 给主窗口，由 `App.tsx` 的 `useTabKeys` 照页签和索引签做；焦点在速记小窗时只认 ⌘W / ⇧⌘W（收起）。⌘1～⌘9 那几行的名字由页面在置顶变了时发过来（`app_menu_index`），Rust 重建菜单。⌘⇧[ ⌘⇧] 只在页面里认。
- **拖动**：模块坞、索引签、柚子瓣的拖动照「拖拽排序」用鼠标事件做（原型用的浏览器自带拖放只是演示）。

## 打开链接

带协议的（`https:`、`mailto:`、`bear:` 等）直接交给系统；`/…`、`~/…` 当作本机文件；其他的（比如 `www.xx.com`）补上 `https://`。

## 模块之间

一个操作要改好几张表时放在一个事务里（可以嵌套，模块互相调用、导入时调用各模块都不冲突），中途出错就全部不算。

- **五花八门、循序渐进**：建出来的每一个当一个模块，键是 `list/编号` 或 `progress/编号`（也是页面地址）；导航里的位置、隐藏、「发给云端」、循序渐进的类型列表（`kinds` 表里 `module` 就是这个键，和随意画画的类型同一套）都按键存，所以编号永远不重用。单选、多选的选项和循序渐进的类型按在列表里的位置配颜色（`--tag-1`～`--tag-8`，超过 8 个从头再来），只是显示，不存。界面的模块列表 = 固定模块 + 从 Rust 读到的建出来的模块。五花八门每条的字段值存成一份 JSON，规则都在 `lists.rs` 里检查；排序、筛选只是页面上的显示。小拾用两个工具（`pomelo_lists`、`pomelo_progress`）查它们，工具说明里不写模块名（不带个人数据）。
- **导入账单**：分两块。账单和行在 `modules/finance/import.rs`（`pomelo.db`，进撤销和导出）：每个文件一批（`fin_imports`），每行留读到的原文（`source_json`）和我核对后的草稿（`draft_json`），确认后才写进 `fin_entries`（一步撤销，几行一个事务）；同金额、同币种、7 天内的已有记录和更早账单里没入账的行列成候选（同来源两边都有单号而且不同的不算；模型点名的那笔不论金额也列进来），没决定的 Rust 挡着不让入账。左边的列表按 `sort_order` 排（新的放最上），改名写 `title`（`name` 留着认原文件），删除只删账单和它的行（入账的收支留着，合并进它的、还没入账的别的行回到待核对）。读账单的是助手 **Importer**（`picky/assistants/importer.rs`）：只用小拾的云端模型（`schedule::route`，开发版是模拟的；本地模型看不了图），只在「钱来钱往 · 收支」能发给云端、钱来钱往没隐藏时。三个命令：`picky_importer_extract` 把文件交给模型：Excel 用 `calamine` 转成带行号的文字（表头是靠上最宽、下面也有同样宽的行的那一行；每 60 行一块，每块都带表头和表头上面的说明），PDF 用 PDFKit 画成图（每 4 页一块，后面的块多带第 1 页看账期），截图原样发；模型答的每一行单独检查（分类得是已有的、算作和币种得是认识的、日期金额得合法），不合格的值不用、记成那一行的疑点；Excel 按行号拿原文，模型没提到的「像交易的行」（和失败那块的行）再问一次，还没有就留一行（没有金额，写明漏了或为什么失败）；提示里带 `today` 和最近 6 个月 1 号的星期几（`calendar`），方便没有月份的截图推月份；日期晚于今天的标疑点；回复太长对半分了再问；全局同时最多 4 个请求。`picky_importer_match` 查重：每份账单每 60 行一块，发这些行和它们日期前后 7 天的账本（`e:` 收支明细，带来源、期间记录带 `until`；`r:` 更早账单里没入账的行）；模型说合并时，只有同金额、同币种、日期够近（手记和固定支出 7 天，账单之间 3 天）、付款渠道不矛盾（`CHANNELS`：账单本身的，否则看文字；两边都看得出又不同才算，要加渠道在这里加一行）、和手记的分类不矛盾才真的合并，其余变成「拿不准」并把那笔列进候选（合并会藏起一笔钱，这里程序把关）。`picky_importer_tidy` 再整理：把没保存过的行的原文和现在的内容发给模型（能改日期、金额、币种、算作、分类、备注、判断疑点），再查一遍重。查重和再整理写之前逐行比对，运行期间我动过的行不写。模型只能走这几步，全部结果都等我入账。提示词清单和模型在 `picky.db` 偏好 `assistant.importer`，发出去时渲染成 Markdown 列表接在内置说明后面。页面上的任务放在 `src/modules/finance/importJob.ts`，离开页面也跑完。`fin_imports.source` 是模型认出的来源，其他版式记 `screenshot`。
- **笔记转待办**：任务记下来自哪条笔记（笔记删了变空）；数据文件里用笔记的记录时间对上，导入时先导笔记再导待办。小拾「拆成待办」和「拆成子任务」一样：模型只列出来，勾选后一步加上。

## 搜索和索引

- **全局搜索**（按字）：Rust 在 SQLite 里逐条比对每个模块要搜的字段（中英文都能找到词中间的字），每个词都出现才算，每类最多 6 条。界面跳到那个模块，由模块页面打开那条记录（`src/shared/open.ts`）。
- **一个入口**：`search/query.rs`，「意思相近」和小拾的搜索都调它。给它一句话、范围和方式（按字、按意思、合并），返回记录在哪、标题、片段、得分和怎么找到的。芝麻开门不进索引；隐藏的模块、云端规则在这里挡。向量或重排服务用不了时照样按字返回。
- **三种方式**：按字用 FTS5（中文两个字一组）；按意思把问题和记录都算成向量比相似度；合并是两种名次合在一起，再用重排模型给前 30 条打分：有把握的（0.1 分以上）排前面，其余保持合并后的顺序（「找房子」这种短词它对什么都给接近 0 分，全按它排会把对的挤下去）。
- **索引和原始数据分开**：`search.db` 只放算出来的东西（每条记录要搜的文字、指纹、全文索引和向量，项目资料、记忆、知识库的分段和向量）；「哪些要建索引」这类选择留在 `picky.db`。
- **后台更新**（`search/indexer.rs`）：用自己的只读连接，每 2 秒看一眼两个数据库有没有被改过（SQLite 的 `data_version`，撤销、导入、恢复都算），有就按指纹比对，只写变了的、删掉没了的。不用在每个命令里挂钩子。
- **向量什么时候算**：只在向量服务本来开着、或按意思搜 / 小拾检索要用时补算，不为改一条记录专门启动服务。重建（`search.db` 新建、换向量模型、换文字规则）例外：自动启动服务，在后台从新到旧算完，期间照常按字找。
- **速度**：向量压成 8 位整数载入内存逐条比（20 万段约 200 MB）；20 万条实测按字约 0.06 秒、按意思约 0.02 秒。再大就换近似检索，所以向量检索做成了能换的部件。
- **全量读取**：年度总结这类要看全部数据的任务不经过检索，直接用各模块的只读函数读全。

## 呦呦漫游（个人网站）

- **内容只在网站文件夹里**：`site.folder` 记位置（默认 `~/Documents/GitHub/personal-website`），不存副本，不进 `pomelo.db`、备份、导出、撤销和搜索；网站的 git 历史就是它的历史。内容格式照它的 `content.config.ts` 和现有文件。
- **运行方式**（`site/mod.rs`，同小拾）：只有正式数据目录的打包版（或 `POMELO_REAL_SITE=1`）用真文件夹、真推 GitHub、用 gh 读 Vercel；其余用数据目录里的副本（`site-sandbox/website`，APFS 复制）和本机的假远端（`site-sandbox/remote.git`），上线结果是模拟的；远端不是本机文件夹时一律不提交、不推送。
- **外部程序**：`/usr/bin/git`（推送靠钥匙串里已有的 git 凭据，要密码就报错、不卡住）；gh 只读上线结果；Node 按网站的 `.nvmrc` 在 nvm 里找。缺哪个只关掉用它的功能，写明原因。
- **本地服务**：`npm run dev` 在自己的进程组里跑（正式 4328，副本 4338），退出 Pomelo 时整组停掉；端口上已有别处启动的就直接用、不停它。启动时设 `ASTRO_DEV_BACKGROUND`，让 Astro 留在前台。
- **发布**（`publish.rs`，后台任务）：fetch 只快进（分叉、冲突、不在 `main` 都停）→ 确认框带着改动的指纹 → `npm run qa`（最多 15 分钟，没过留最后几十行输出）→ 再确认没落后、指纹还对，`git add -A`、commit（文字原样）、`push origin main`，不强推、不改历史 → 每 8 秒用 `gh api` 读 Vercel 状态，15 分钟没结果写「没等到」。改动清单（`changes.rs`）是 `git status` 加还没推的提交，按路径认出是哪类内容。
- **读写内容**（`yaml.rs`、`doc.rs`）：读用 `yaml-rust2`（键保持顺序）；写是 js-yaml 4.3 `dump` 的逐行移植（网站原有文件就是它写的），JSON 照 `JSON.stringify(…, null, 2)`。键原地改、不认识的原样留、没变的文件不写、写之前比对读进来时的指纹。85 组对照测试，另有只读测试拿网站全部内容文件和 Node 跑的 js-yaml 逐字比对。各页各一个文件（`wander.rs` `now.rs` `about.rs` `career.rs` `terms.rs`）。
- **资源库**（`images.rs`、`registry.rs`）：内容只写引用，保存时检查引用的是资源库里的文件。加文件都走 `site_files_add`：超过 1.5 MB 的图片用 `sips` 转 JPEG、缩长边；资源库里有一模一样的就用它，网站别处有一样的就拒绝；否则存进资源库并按去处自动登记。删之前照网站 `asset-reference-report.mjs` 的规则扫引用。界面经 `pomelo-site://localhost/<网址>` 显示网站里的图片（只认 `public/` 下的）。
- **预览和编辑器**：Rust 开一个 `site-preview` 窗口装本地服务的那一页（它不能调用 Pomelo 的命令）；编辑器 `MdEditor.tsx` 和念念不忘的输入框同一套（`shared/editable.ts`）。

## 小拾（AI）

- **同时生成**（`chat.rs` 的 `Runs`）：每个对话一个生成位置，对话、定时任务、助手、简报各写各的。本地模型一次答一个（`--parallel 1`），请求在 `provider.rs` 排队；云端不排队。云端还没收到内容时遇到 429、5xx、流里的错误或连不上，等 2 / 5 / 10 秒（照 `Retry-After`，最多 20 秒）重发，最多 3 次。本地模型在回答时不能停、不能换别的本地模型。
- **小拾服务**：一个统一的「发消息、流式收回复」接口，背后是本地模型（8080，OpenAI 兼容）或六家云端（只连固定的官方 HTTPS 地址；Anthropic 用它的 Messages 接口，其余是 OpenAI 那种）。回复、思考、用量边收边交给界面，定时存进 `picky.db`，中断时保存已收到的；出错只显示固定的中文提示。
- **思考**：每次调用都说要不要思考，只有「能开关」的模型收到开关，要思考的多留回复长度（`Route::with_thinking`）。模型不收某个设置就去掉再发一次，并记住到退出；阿里云的内容审核拦下时直接这样说，不重试。查数据的那几轮按各家要求原样发回思考内容（签名等），以前的问答只发文字。
- **思考强度**：只有一个入口，`provider.rs` 的 `level_for`（`stream` 开头）：请求选的强度模型有就用，否则用模型固定的默认，再没有就不发；高强度时在短的回复上限上加余量（`Options.room_fixed`：调用方算过了就不加）。所以没选强度的调用都不用改。词原样发给接口，400 就去掉再问一次并记住（`模型#词`）。能选的地方存「开关 + 强度」：`sessions`、`schedules`、偏好 `brief.effort`、`assistant.translate`、`rater.options`、Seeker 的 `options`；Pub2MD、Importer、面板帮手（偏好 `assist.model` 模型、`assist.level` 思考）存 `cloud::Level`。界面都由 `Thinking.tsx` 按当前模型列选项（`ThinkingButton`、`LevelPicker`，助手设置页的 `ModelRow.tsx`）。**中间步骤**（对话压缩、读长文件、年度总结的每月阅读）不传强度，用模型的默认，只有最后的回答用选的。Pub2MD 查术语直接连接口的几条路（`search.rs`）照 `CloudModel::effort`。
- **本地模型**：读 `~/Documents/LLM/config/models.json`（聊天、向量、重排三类），用 `llmctl.sh` 启停，查 `/health` 判断状态。聊天模型同一时间一个（8080），向量（8081）、重排（8082）要用时自动启动；小拾启动的闲置 30 分钟后停、退出柚儿园时停，别处启动的不碰。上下文按名字里的大小限制。这些控制只给界面和菜单栏，不交给 AI。
- **数据**：`picky.db` 存对话、消息版本树、调用记录、附件和分段文字、模板、预设、摘要、记忆、项目资料、出处、卡片、定时任务、简报、知识库的选择（表见[数据结构](schema.md)）；分段和向量在 `search.db`；文件副本在 `picky-files/`。
- **读文件**（`files.rs`、`office.rs`、`reading.rs`）：添加时读一次存成分段文字。表格用 `calamine`、CSV 自己解析，大表格只存表头和前 50 行（「查表」每次从副本现读整张）；网页在 Rust 里下载（20 秒、5 MB 以内）取正文成 Markdown；图片不存文字，发给云端前在临时文件夹里用 `sips` 缩小；没有文字的 PDF（扫描件）、只有图片的 Word / PowerPoint 当附件时存一句「没有文字、共几页 / 几张图」（`prepare` 里，知识库照旧当扫描件只认文件名），云端模型用读文件的 `look` 看。追问时前面问题的附件另起一段，标成「前面附过」。
- **挑选和检索**：记忆和资料段落先按向量相似度取一批（记忆 12 条、资料 20 段，0.30 以上），再用重排模型挑出至多 6 条；重排用不了就只按相似度（0.35 以上）。知识库同样。
- **出处**（`cite.rs`）：一次回复拿到的东西统一编号（同一条记录一个号），随回复存进 `picky.db`；私密对话不在结果里；「读整条」读之前再按能读和云端的规则查一遍。
- **查数据**（`data.rs`）：用模型的工具调用。Rust 定义每个模块的只读查询（统计和页面共用一个函数），先检查能不能读、这次能不能发给云端，再查、截短后交回；钱来钱往按两块算云端（`cloud_key`：资产 = 账户、余额、持仓，其余是收支），查询、页面、卡片、搜索结果都按自己那块挡，偏好里旧的「钱来钱往」开关当资产的；一次回答最多 4 轮，查到的存进 `picky.db`。小窗只告诉 Rust 当前页面和记录编号，内容由 Rust 按同样的规则取。
- **改数据**（`act/`）：七个模块共 14 个写数据的工具，模型只能「提议」：Rust 读它给的字段（日期词按今天算、名称对上已有的），按名称里的字去找要改的那条（几条就都列出来让我选），用模块自己的函数在最后撤回的事务里试写一遍，前后一比就是卡片；告诉模型的话照抄卡片。查数据的 4 轮之后还有一轮只给写数据的工具。确认时 Rust 按卡片里存的写入，整张一步 ⌘Z。隐藏的模块不给工具；云端不允许的模块一律拒绝。还没确认的卡片能改：每一条有个编号（第几条回复的第几条），工具结果里告诉模型，前面回复里还没确认的卡片列在说明里（只列这个模型能看的模块）；模型用同一个工具加 `replace`（编号）重新提议，Rust 照样检查、试写后把那一条换掉（这条回复的或前面的，只限这个对话当前显示的分支）。新书影先用书单 / 影单检索补作者、国家、类型；模型自己说了作者而查到的是别人时，算查到了同名的另一部，用模型自己的。
- **问我（ASK，`ask.rs`）**：工具 `pomelo_ask_user`，只在云端模型的对话里提供（`chat.rs` 的 `generate` 判断，定时任务和复盘记录不给）。模型调用后，卡片存进 `run_asks`、发给页面，这条回答的后台任务停在 `ask::Gate`（一个 oneshot）上，不发任何请求；`picky_ask_answer` 记下回答、把文字交回去，变成工具结果，循环接着走（只问了我的一轮不算查数据的轮数，问题不合格的算，免得停不下来）。这期间对话的位置一直占着，所以输入框发不了。停止时任务被结束、卡片改成没回答。退出时回答记成中断、卡片留着；之后回答时已没有任务在等，命令返回 `followUp`，页面把它当新消息发出，这样不用保存模型工作的中间状态。在这个对话里开始新的回答时，留下的卡片关掉。
- **润色、补全、一句话填好**（`assist.rs`）：一问一答，模型和思考照「设置 → 小拾」的「面板帮手」（默认小拾现在选的、思考 · 模型的默认）；Rust 写好提示（一句话填好附上今天前后的日历和已有的分类、分组、渠道、模板），把回答读成字段再检查一遍才交给面板，保存照常走各模块的命令。呦呦漫游在 `data.rs` 里是「只帮忙、不读」的模块（`HELP_ONLY`）。
- **插件库**（`skills/`）：开着、Key 齐了、并且「自己决定用」或这一条点名要它，才给模型这个工具；点名要的在系统消息里写明必须先用，点名联网的 Rust 先拿问题本身搜一次。不用 `tool_choice: required`（有的服务不认）。查到的都编号成出处、记进「查了」。

- **定时**（`schedule.rs`）：后台循环每 30 秒看一次到点的任务，跑的时候和发消息走同一条路，只是只读、系统消息说明我不在。要用的本地模型没运行就先启动，跑完只停它自己启动的。「上次跑到哪」放在单独的表里，不进撤销。
- **今日简报**（`brief.rs`）：Rust 先用 `data.rs` 读好待办、该提醒的日子、投递、最近两周的笔记（每块有上限），一次请求（系统消息是提示词：偏好 `brief.prompt`，空就用程序里的 `DEFAULT_PROMPT`；日期和读到的数据放在用户消息里），最多等 5 分钟；不占对话的生成位置。
- **年度总结**（`yearly.rs`）：不用查数据的工具，Rust 先读好全年和算好的数字（含去年同期的数字和差值、去年的年度总结）。放得下就一次发；放不下就按月整理要点（存进 `month_summaries`，读的内容没变就直接用），再拿要点写全年。写的是哪一年记在 `year_runs`。「定时」里画的流程图是 `yearly.rs` 的 `FLOW`（和插件库的 `Flow` 同一种），改了流程要一起改。
- **知识库**（`knowledge.rs`）：`picky.db` 只记库、文件夹、网页正文、云端开关和对话、项目选的库，都能撤销；文件清单、分段和向量在 `search.db`（后台扫描只写它，不挡 ⌘Z）。不监听文件：打开小拾页、打开知识库对话框和每 10 分钟比一遍大小和修改时间；建索引一次一个，文字没变的段落沿用旧向量。「打开文件」先检查路径没出文件夹。
- **助手**（`assistants/`）：设置和上一次的结果放在 `picky.db` 偏好（`assistant.<名字>`），不进撤销和导出。**Importer** 见上面「导入账单」。**Translator**（`translate.rs`）：Rust 拼提示词；长文按段切块依次流式翻，后一块带上前一块译文的结尾（300 字以内）对齐译法；在后台任务里跑，结果每秒存一次、页面轮询，离开、刷新都不丢。**呦呦漫游 · 按中文起草**（`site.rs`）用同一套 `translate_with`，结果只在内存。
- **Pub2MD**（`assistants/pub2md/`，流程在 `job.rs`）：
  - **提取**：直连 Mathpix（手写 multipart 上传，要分页标记、不让它拿去改进；pdf_id 一拿到就存，同样的文件用上次的原始结果）。原页图用 PDFKit 画成长边 1568 的 JPEG；图片先用 NSImage 合成 PDF（认 EXIF 方向）。
  - **切块和流程**：`mmd.rs` 认出页、能切的地方和论文各部分，`chunk.rs` 切草案、纠正 Supervisor 不合规矩的改动；每块的下一步由 `job.rs` 排，JoinSet 同时做几块，术语表没好之前不翻；每一步存进 `.pub2md/job.json`，「继续」从那里接着做。
  - **检查和修补**：`check.rs` 只比文字（细则在它开头），`prompts.rs` 修模型常出的小毛病；回复被思考占满时多留长度再试一次；请求失败、内容审核按需求里的规则换备用模型。Supervisor 的 JSON 读不了先补没转义的引号，术语表截断时取完整的条目；回答长度按思考强度多留（低 8K、中 16K、高 32K）。
  - **联网查术语**（`search.rs`）：各家自带的搜索（DeepSeek Search / Fetch、Aliyun `enable_search`、OpenAI `web_search`、Anthropic web_search / web_fetch、Google `google_search`），其余用 Tavily。简繁用 `script.rs`（ferrous-opencc，s2twp / tw2sp，跳过代码、链接和网址）。
  - **另存为**：Mathpix `/v3/converter`，图片换回提取时记下的 Mathpix 链接（30 天内有效）。
  - **预览**：mathpix-markdown-it 浏览器版（单独打包，打开预览才加载），放进不能跑脚本的 `sandbox` iframe；提示词页的说明和真正发出的用同一套函数拼。
  - 页面命令都是 `async`，先取完数据库和钥匙串再拿排队的锁；「删除」只删 Pub2MD 建的文件夹，移到废纸篓。设置和最近 10 份在 `picky.db` 偏好，排队的只在内存；模拟版用 PDFKit 读出的文字代替 Mathpix。
- **Work**（`work.rs`、`word.rs`、`skills/toolbox.rs`）：「保存为 Word」把回答写成自己生成的 .docx（真正的标题、列表、表格、引用、代码样式，出处列在文末），只在你点了以后、在你选的文件夹里新建，不覆盖。改文件只能改 Rust 列出的文件（附件的原文件、旧问题选的文件、知识库里的文件），读成编号的段落；模型的提议逐段检查后放进卡片（一条回复一个文件，记下文件的指纹），写入时文件变了就不写；Word 只改变了的字，其余一个字节都不动，改不了的拒绝（细则在 `word.rs` 开头）。
- **Excel 工具箱**（`excel.rs`，不加新库，zip + quick-xml；calamine 只读）：读整个 .xlsx，只重写动到的表：没改的格子保留原来的 XML，别的部分原样复制；文字写成内联字符串，不碰共享字符串。一次提议里的行号都按读到的算：先改格子，再从下往上加删行，挪动时重写所有表的公式（`rewrite` 认 A1 引用、范围、整行整列、Sheet!引用，跳过字符串、函数名和结构化引用）、合并格、条件格式、数据验证、超链接、筛选、定义的名称，共享公式先展开。挪不好的（图表、表格对象、批注、透视表、跨几张表的公式）直接拒绝。和 Excel 不同的一处：加在一个范围最后一行后面、而公式在这几行外面时（合计在明细下面），范围扩到新行（`grows`）；提议的公式用到自己所在的格子不收（`names_itself`）。写入时去掉 calcChain.xml、要求打开时全部重算。读大文件在数据库锁外（`excel_plan`，再 `excel_commit` 放进卡片）。
- **定时任务的工具**（`chat.rs` 的 `read_only`，`lookup_plan`）：不给写 Pomelo 数据的工具和题库；给工具箱（卡片按 `run_id` 存，留在那次对话里）；联网搜索不看「自己决定用」（`Ctx.scheduled`），开着、有 Key 就给。
- **看文档里的图片**（`office.rs`）：Word、PowerPoint 从 zip 里按文档顺序取图（`relations` 对上图片文件，用附近的文字或页码说明在哪）；PDF 用 Quartz 的 PDF 对象数每页的图（`pdf.rs` 的 `image_pages`，PDFKit 不给这个），看的时候用 PDFKit 画整页。读文件的 `images`、`look` 在 `chat.rs` 的 `file_images`，查知识库的在 `knowledge.rs`，都在数据库锁外读文件、只给云端模型、一个回答共用 8 张的上限，图片跟在这一轮的结果后面发。
- **体检**（`health.rs`）：只读、现算，结果用全局搜索的 `Hit`，页面照 ⌘K 打开记录。
- **云端 Key**：只在钥匙串（和插件库的 Key 同一组），界面只显示「已保存」；不进数据库、备份、导出和日志。
- **空间管理**：算数据库和 `picky-files/` 的大小，列出每份副本被谁用着；删副本只删文件、留下记录（「文件已删除」）。

- **Seeker**（`assistants/seeker.rs`、`seeker/`）：资料、草稿、导出记录都在 `picky.db`，不存整份简历的副本。页面打字停一下自动存（`seekerDraft.ts` 排队，结构操作前先存完），每次保存一步撤销。导入只读 `transfer/` 认得的 Markdown，按「来源（文件#标题:第几个）」对上以前导入的。发给模型的资料在 `model.rs` 的 `context` 现拼；规则是「标题 + 分点」（`catalog.rs` 的 `rules_markdown`，Rater 也用），旧规则正文读出来时转成分点（`normalize`），下次保存才换。模型每次只调一次、没有工具；模型和思考按功能选（`catalog.rs` 的 `Settings::of`，没单独选的跟默认；以前的选材、审查模型读出来时转过来：`StoredSettings`）。选材和润色一条素材的回答按编号检查后给差异，确认才写；审查、润色要点、Summary 的回答变成批注（`notes_from`），调用结束时 Rust 自己存进草稿（一步撤销），页面关了也不丢；发给模型的草稿带短编号（`outline`：S1、E1、P1），对不上的那条略过。页面的调用放在 `seekerJobs.tsx`（不跟着页面卸载）。开发版打不开真的 Seeker 文件夹（`output.rs` 的 `allowed_path`）。岗位关联、「做简历」、公司资料都先读 `pomelo.db` 再锁 `picky.db`，不嵌套。
