# 技术架构

## 基本原则

- **个人、轻量**：只给我一个人在一台 Mac 上用，不做账号、协作、云端、跨平台。
- **够用就好**：能用简单办法的，不用复杂办法。
- **数据能长期保存、随时带走**：App 随时可以换掉，数据不丢。
- **默认离线**：只有 AI 联网搜索和可选的云端模型（默认关）会联网。

## 技术选型

| 部分 | 选择 |
|---|---|
| 桌面应用 | Tauri 2 |
| 界面 | React + TypeScript + Vite，Tailwind CSS；少量自己写的组件，不用组件库 |
| 数据层 | Rust + SQLite |
| 辅助脚本 | TypeScript（Node） |

## 分层

```
界面（React） ──┐
               ├── 调用命令 ──▶ Rust 命令层 ──▶ SQLite
AI 助手（以后）──┘              业务规则、校验都在这里
```

- 只有 Rust 端读写数据库，界面只调用 `books_list` 这样的命令。
- 以后 AI 用的工具就是这些命令，AI 永远碰不到数据库本身。

## 数据存放在哪里

| 位置 | 放什么 | 备份 |
|---|---|---|
| `/Applications/Pomelo OS.app` | App 本体 | 不用 |
| `~/Library/Application Support/Pomelo OS/` | 真实数据：`pomelo.db`（含设置）、`backups/` | **要** |
| `~/Library/Application Support/Pomelo OS Dev/` | 开发用的测试数据 | 不用 |
| macOS 钥匙串 | 芝麻开门 Touch ID 用的钥匙；以后的 API Key 等密钥 | 不进备份 |

不要把数据库放进 iCloud、Dropbox 等同步文件夹，同步可能把它弄坏；想异地保存，就复制**备份文件**。

## 开发版和正式版

同一份代码的两种运行方式，区别只在数据目录：

- **正式版**：「应用程序」里的 App，我日常使用，读写真实数据。
- **开发版**：开发时直接从代码运行，读写测试数据，随便清空。

分开是因为开发中的代码可能有 bug，数据库升级脚本也要先在测试数据上试好。阶段验收后运行 `pnpm app:install` 更新正式版；新版第一次打开时，会先自动备份再升级。「应用程序」里只应该有一个 Pomelo OS。

## 数据库升级

- 每次改结构都新增一个编号脚本（`src-tauri/migrations/`），已经用过的脚本永远不改。
- App 启动时如果需要升级：**先自动备份**，再逐个执行。
- 数据库版本比 App 新（比如装回了旧版）时，App 拒绝打开，防止写坏数据。

## 备份与导入导出

| | 快照备份 | 数据文件（JSON） |
|---|---|---|
| 是什么 | 整个数据库的副本，放在数据目录的 `backups/` 里 | 所有模块的数据，人能看懂 |
| 用途 | 出问题时恢复 | 长期归档、换工具、从 Excel 导入 |
| 什么时候做 | 每天第一次打开、升级前、覆盖导入前、恢复前自动做；也可以「立即备份」 | 在设置里「导出…」 |
| 怎么用回来 | 设置里的备份列表，点「恢复」 | 设置里「导入」 |

- **每日备份**保留最近 30 份，更早的每个月只留最后一份。其他备份不会自动删除，想清理可以在 Finder 里删。
- **恢复**会把当前的全部数据换成那份备份；恢复前先自动备份当前数据。老版本的备份恢复后会自动升级；损坏的、或者比 App 新的备份会被拒绝。
- **导入**时，文件里只要有一条不合格就一条都不导入；覆盖已有数据前会先确认并备份。
- 备份文件名里写着时间和原因，比如 `pomelo-20260929-093000-daily.db`（每日）、`manual`（手动）、`before-v7`（升级到版本 7 前）、`before-import`、`before-restore`。

## 芝麻开门的安全

- **加密**：设置主密码时随机生成一把「密码库钥匙」，每条密码都用它加密（XChaCha20-Poly1305）后才写进数据库。主密码经过 Argon2id（256 MB、3 轮，一次约 0.3 秒）算出另一把钥匙，把密码库钥匙锁起来存着。主密码本身哪里都不存。
- **打开**：输主密码，或者用 Touch ID 从钥匙串取出密码库钥匙。规则（3 次失败、3 天、更新后）都在 Rust 里判断。打开后钥匙只在内存里，5 分钟没用就清掉（按真实时间算，电脑睡眠也算）。
- **谁读得到**：数据库、备份、导出文件里都没有明文；任何读文件的程序（包括 AI 编程助手）只能看到乱码。钥匙串里的那份，别的程序要读，系统会弹窗要电脑登录密码。复制密码时由 Rust 直接放进剪贴板（标成「隐藏」，剪贴板工具不记录），30 秒后清掉；列表里也从不带密码。
- **AI**：以后的 AI 工具不会包含任何芝麻开门的命令。
- **代价**：主密码忘了就打不开，没有找回办法。

## 撤销

- 每个改数据的命令执行时，用 SQLite 自带的「会话」功能记下改了哪些行（连同一起删掉的子项）。⌘Z 把这份记录反着应用一遍，⌘⇧Z 再正着应用一遍。
- 最多记 100 步，只在内存里，关掉 App 就没了。设置（比如侧栏顺序）不算进去。
- 如果数据在这之间被改过、对不上了，就拒绝撤销并清空记录，不会写坏数据。导入和恢复备份也会清空记录。

## 拖拽排序

界面拖完后，把屏幕上这几条的新顺序交给 Rust。可以只是一组里的一部分（比如没做完的任务、筛选后的课节）：它们在自己原来的位置之间互换，看不到的条目位置不变。Rust 检查这些条目确实属于这一组，再重写 `sort_order`。拖拽是自己用鼠标事件做的，因为 macOS 的网页控件对原生拖放支持不好。

## 打开链接

任务的链接交给 Rust 打开：带协议的（`https:`、`mailto:`、`bear:` 等）直接交给系统；`/…`、`~/…` 当作本机文件；其他的（比如 `www.xx.com`）自动补上 `https://`。

## 模块之间

一个操作要改好几张表时，在一个事务里完成（用可以嵌套的事务，所以模块互相调用、导入时调用各模块都不会冲突），中途出错就全部不算。

## 全局搜索

Rust 的 `search.rs` 列出每个模块要搜的字段（芝麻开门不在里面），每个词都出现才算找到，每类最多 6 条。界面跳到那个模块，由模块页面打开那条记录（`src/shared/open.ts`）。数据不多，直接在 SQLite 里逐条比对，不建索引。

## 首页

首页的数字和清单由 Rust 的 `home.rs` 一次算好（只读，不存东西），隐藏的模块不算；今天的待办直接用一步一步的列表。每次打开首页都重新算一遍。

## 每天的例行检查

每天第一次打开 App、或者 App 开着过了零点，Rust 会做三件事：每日备份；把时间段已经结束、或者已经全部打完的打卡任务标为完成；把到日子的固定支出记上（漏掉的几次一起补）。这些不进撤销记录（撤销了下次还会再做）。

## 图表

回看、钱来钱往和首页的图表是自己用 SVG 画的（柱状图、折线、圆环、排行条、预算条），不引入图表库。颜色用一套检查过色弱可读性的固定顺序，深浅两种模式各一套；每张图旁边都有对应的数字或清单，不只靠鼠标悬停看数。

## 占用空间和内存

- **实测**：App 本体约 7 MB；运行内存约 85 MB（不到这台 Mac 内存的 1%）；导入全部现有数据（Excel、待办、投递、179 条笔记）后，数据库约 0.5 MB。
- **估算**：加上待办、财务、AI 对话记录，数据库十年也在几百 MB 以内。真正占空间的会是照片类附件，存的时候会先压缩。

- **本地模型**由 llama.cpp 运行，放在 `~/Documents/LLM`，用 `scripts/llmctl.sh` 启动和切换；同一时间只跑一个，接口是 `http://127.0.0.1:8080/v1`。14B 模型约占 9 GB 内存。Pomelo 只连接它，不负责下载模型。
- **云端模型**可以接，但默认关闭。
- AI 和界面一样，只能通过 Rust 命令读写数据；改数据前必须我确认。
