# 技术架构

## 基本原则

- **个人、轻量**：只给我一个人在一台 Mac 上用，不做账号、协作、云端、跨平台。
- **够用就好**：能用简单办法的，不用复杂办法。
- **数据能长期保存、随时带走**：App 随时可以换掉，数据不丢。
- **默认离线**：联网的只有柚子的云端模型、插件库、「添加网页」、Pub2MD（Mathpix）、呦呦漫游的发布和一网打尽的网站图标。

## 技术选型

| 部分 | 选择 |
|---|---|
| 桌面应用 | Tauri 2 |
| 界面 | React + TypeScript + Vite，Tailwind CSS；少量自己写的组件，不用组件库 |
| 数据层 | Rust + SQLite |
| 柚子（AI） | Rust 用 reqwest 连模型、收流式回复；消息排版用 markdown-it、highlight.js、KaTeX |
| 读写文件 | PDF 用 PDFKit、读 Word 用 `textutil`、缩图片用 `sips`（都是 macOS 自带）；PowerPoint 和改 Word、写 Word 用 `zip` + `quick-xml`，表格用 `calamine`，网页正文用 `dom_smoothie` |
| 辅助脚本 | TypeScript（Node），不用 Python |

## 分层

```
界面（React） ──┐
               ├── 调用命令 ──▶ Rust 命令层 ──▶ SQLite（pomelo.db · youzi.db · search.db）
柚子的 Agent ───┘              业务规则、校验都在这里
                               │
                               └─ 柚子服务 ──▶ 本地模型 8080 · 向量 8081 · 重排 8082 · 五家云端
```

- 只有 Rust 读写数据库，界面只调用 `books_list` 这样的命令。
- 柚子的工具也是 Rust 命令（只读查询、「提议」），AI 碰不到数据库；启停模型、芝麻开门、导入导出、备份恢复、写文件永远不做成工具。
- 用模型都经过「柚子服务」：聊天、定时任务、简报、润色补全、翻译都一样。本机其他程序要用本地模型，照旧直接连 8080。

## 数据存放在哪里

| 位置 | 放什么 | 备份 |
|---|---|---|
| `/Applications/Pomelo OS.app` | App 本体 | 不用 |
| `~/Library/Application Support/Pomelo OS/` | 真实数据：`pomelo.db`（生活数据和设置）、`youzi.db`（柚子）、`backups/` | **要** |
| 同上的 `attachments/` | 笔记、任务、目标的附件（原文件的副本） | 不进每日备份，交给 Time Machine 这类工具 |
| 同上的 `youzi-files/` | 柚子的附件和项目资料（原文件的副本，和上一行各存各的） | 不备份，也不需要另外备份（你定的） |
| 同上的 `search.db` | 搜索索引：从数据算出来的分段和向量、知识库文件夹的清单 | 不备份、不导出，删了自动重建 |
| 同上的 `janitor.db` | DevJanitor 上次扫描的结果（要画的文件夹、一键清理和只列出来的条目） | 不备份、不导出，删了下次扫描重建 |
| 同上的 `icons/` | 一网打尽的网站图标（一个网站一个文件） | 不备份、不导出，删了重新取 |
| `~/Library/Application Support/Pomelo OS Dev/` | 开发用的测试数据；`janitor-sandbox/` 是 DevJanitor 的「假 Mac」 | 不用 |
| macOS 钥匙串 | 两项：「Pomelo OS Agent」（云端 Key、插件库和 Pub2MD 的 Key 合成一项）、「Pomelo OS 芝麻开门」（Touch ID 用的钥匙） | 不进备份 |
| `~/Documents/LLM` | 本地模型、模型清单、启停脚本 | 独立的文件夹，由 Claude 维护；Pomelo 只读清单、调脚本 |
| `~/Documents/GitHub/personal-website` | 个人网站（呦呦漫游编辑、发布的就是它） | 独立的项目，自己的 git 历史和 GitHub 仓库 |

不要把数据库放进 iCloud、Dropbox 等同步文件夹，同步可能把它弄坏；想异地保存，就复制**备份文件**。

## 开发版和正式版

- 同一份代码，区别只在数据目录：正式版是「应用程序」里的 App（真实数据），开发版直接从代码运行（测试数据，随便清空）。阶段验收后 `pnpm app:install` 更新正式版，新版第一次打开时先自动备份再升级。「应用程序」里只应该有一个 Pomelo OS。
- **签名**：用固定的自签名证书「Pomelo Self-Signed」，系统认得每次更新的是同一个 App，钥匙串里的 Key 更新后还能读。但自签名证书没有团队编号，钥匙串只能按每个版本认，所以每次更新后还要授权：Key 都合在一项里，打开新版时弹一次；芝麻开门在第一次用 Touch ID 前弹一次（输主密码后存 Touch ID 的钥匙时）。弹框里输登录密码、点「始终允许」。要完全不弹得换苹果的开发证书（要装 Xcode 或付费账号），你选了现在这样。
- **开发版和测试里的柚子只用模拟的**：模拟的模型清单、启停和回复，Key 只在内存；不启停我的模型、不连真实接口、不碰钥匙串。只有正式数据目录的打包版连真实的；开发版要接真模型用 `POMELO_REAL_MODELS=1 pnpm app:dev`（先问我）。云端模型我在正式版里自己测。
- **编译缓存**：Rust 的编译结果（`src-tauri/target`）每换一次编译方式就多存一份，只增不减（曾经到过 70 GB）。开发编译时依赖不带调试信息、自己的代码只带行号，一次完整的编译测试约 3 GB；`pnpm check`、`app:dev`、`app:build`、`app:install` 和每次开 Claude Code 会话时，超过 20 GB 就整个清掉（`scripts/clean-build.sh`，下次编译从头编，约一分半）。

## 数据库升级

- 每次改结构都新增一个编号脚本（`src-tauri/migrations/`），用过的永远不改。`youzi.db` 有自己的一串脚本和版本号。
- App 启动时需要升级：**先自动备份**，再逐个执行。数据库比 App 新（比如装回了旧版）时拒绝打开。
- `search.db` 只有版本号、不升级：对不上就删了重建。

## 备份与导入导出

| | 快照备份 | 数据文件（JSON） |
|---|---|---|
| 是什么 | 整个数据库的副本，在 `backups/` 里 | 所有模块的数据，人能看懂 |
| 用途 | 出问题时恢复 | 长期归档、换工具、从 Excel 导入 |
| 什么时候做 | 每天第一次打开、升级前、覆盖导入前、恢复前自动做；也能「立即备份」 | 「设置 → 导出…」 |
| 怎么用回来 | 设置里的备份列表，「恢复」 | 设置里「导入」 |

- **每日备份**：`pomelo.db` 留最近 30 份，`youzi.db` 留最近 7 份，更早的每个月只留最后一份；两个库分开显示、分开恢复。升级前、导入前、恢复前的备份每种各留最近 3 份（每天做每日备份时清）；手动备份不自动删。
- **恢复**把当前数据整个换成那份备份（先备份当前的）；老版本的备份恢复后自动升级，损坏的或比 App 新的拒绝。
- **导入**时文件里只要有一条不合格就一条都不导入；覆盖前先确认并备份。
- 文件名写着时间和原因：`pomelo-20260929-093000-daily.db`、`manual`、`before-v7`（升级到版本 7 前）、`before-import`、`before-restore`；柚子的以 `youzi-` 开头。

## 附件

- **存**：Rust 把文件复制到 `attachments/`（随机名、只有你的账户能读写），同样的内容（按 SHA-256）只存一份；界面只拿到编号、名字、大小。
- **看**：图片通过 `pomelo-file://localhost/<编号>` 显示，Rust 只按编号给已经存下的图片；其他文件交给 macOS 用默认程序打开。
- **拖进来、粘贴**：交给落点所在的那一块（正在写的笔记、打开的任务面板、目标对话框；都不是就给最近打开的那块）。粘贴的截图没有路径，界面把内容直接交给 Rust 存。
- **删**：删记录不删副本（这样能撤销），没人用的在「设置 → 数据 → 附件」里清理。

## 芝麻开门的安全

- **加密**：设主密码时随机生成一把「密码库钥匙」，每条密码和每个分类名都用它加密（XChaCha20-Poly1305）后才写进数据库；明文的只有顺序、分类编号、归档这几个数字。主密码经过 Argon2id（256 MB、3 轮，约 0.3 秒）算出另一把钥匙，把密码库钥匙锁起来存着。主密码本身哪里都不存。
- **打开**：输主密码，或用 Touch ID 从钥匙串取出密码库钥匙；规则（3 次失败、3 天、更新后）都在 Rust 里判断。打开后钥匙只在内存里，5 分钟没用就清掉（按真实时间算，睡眠也算）。
- **谁读得到**：数据库、备份、导出文件里都没有明文，任何读文件的程序（包括 AI 编程助手）只看到乱码。钥匙串里那份，别的程序要读系统会弹窗要登录密码。复制密码由 Rust 放进剪贴板（标成「隐藏」，剪贴板工具不记），30 秒后清掉；列表里从不带密码。
- **还剩的口子**：① 钥匙串里 Touch ID 那份只靠电脑登录密码挡着。② 拿到数据库或备份的人能离线一个个试主密码（每次约 0.3 秒），主密码越长越难。③ 复制后的 30 秒里别的程序读得到剪贴板；密码「显示」时能截屏的程序看得到。④ 正式版没开「强化运行时」，以你身份运行的恶意程序理论上能注入 App。能加固的（「只用主密码」开关、强化运行时），你选了保持现状。
- **代价**：主密码忘了就打不开，没有找回办法。

## 撤销

- 每个改数据的命令执行时，用 SQLite 自带的「会话」功能记下改了哪些行（连同一起删掉的子项）；⌘Z 反着应用一遍，⌘⇧Z 再正着应用。`pomelo.db` 和 `youzi.db` 分开记。
- 最多 100 步，只在内存里。设置（比如导航顺序、模块坞的分类）不算；发消息、生成回复、建索引、删副本、后台自己跑的（例行检查、定时任务、简报）不算，可撤销的编辑也不碰它们记的东西，免得 ⌘Z 被挡住。
- 数据在这之间被改过、对不上了，就拒绝撤销并清空记录，不会写坏数据。导入和恢复备份也清空记录。

## 拖拽排序

界面拖完后把这几条的新顺序交给 Rust。可以只是一组里的一部分（比如没做完的任务、筛选后的课节）：它们在自己原来的位置之间互换，看不到的条目不动。Rust 检查这些条目确实属于这一组，再重写 `sort_order`。拖拽用鼠标事件自己做（macOS 的网页控件对原生拖放支持不好）。

一网打尽也是树（`BookmarksPage.tsx`，照标签树的写法）：一次拖动交给 Rust「这几条放进哪个文件夹、放在哪一条前面」（`bookmarks_place`），Rust 查过不会把文件夹放进它自己里面、网址不会放到最外层，再给那个文件夹的行重新编号，一步 ⌘Z。最外层只有文件夹：页面没有「一网打尽」那一行，打开时进上次看的文件夹（`settings` 的 `bookmarks.at`），没有就第一个。落点用 `data-drop-folder`（树、路径、文件夹行）和 `data-row`（列表里的行，按上下半边算前后）；树里的文件夹行（`data-tree`）上下边算前后，中间算移进去，展开的文件夹下边算它第一个子文件夹的前面。

念念不忘的标签树是树，单独写在 `TagTree.tsx`（不用 `shared/sortable`）：一次拖动交给 Rust「这个标签放到哪一层、那一层的新顺序」，换了一层先改名再排，一步 ⌘Z。标签本身在正文里，顺序记在标签设置里（按完整路径）。

## 写字的输入框

`src/shared/editor/`：`LiveText` 是共用的底子：一个只收纯文字的可编辑框，文字是唯一的数据，每改一次按行重画、按位置放回光标（`editable.ts`），自带 ⌘Z、输入法、粘贴、列表续行、⌘ 快捷键加标记和「打 # 出提示」这类光标下的小列表（固定定位，挂在页面或所在的对话框上，不会被滚动的框裁掉）。刚回车出来的空行先按「要写的那一段」画（整行高、带段距），光标离开才缩回空行。长什么样由 Flavor 定：`lite.ts` 是念念不忘的格式（念念不忘、速记小窗用 `LiteEditor`，以后要写字的模块也用它，`tags` 可不要），`markdown.ts` 是 Markdown 的 Flavor（能给「只有一张图的行」配图片地址）：呦呦漫游的 `MdEditor.tsx` 用它（配作品的图片），写提示词的框都用 `MdField.tsx`（外观同多行输入框，自己滚动，没有图片）。

- **右键的那条纸**（`MdMenu.tsx`）：`LiveText` 自己接右键，列出 Flavor 的 `formats`（包住选区、给选中的每一行加开头、加一行），再是两个图标库。新 Flavor 写上 `formats` 和 `linePrefix` 就有。
- **字里的图标**（`inlineIcon.ts`）：`:pm-<名字>:` 是柚儿园的图标（名字是图标库的键，`shared/iconLibrary.tsx`），两个 Flavor 都把它画成一个光标进不去的小块（`contenteditable=false`，里面藏着这几个字，所以框里的文字、复制出去的、存下来的都没变）；`editable.ts` 的 `pointAt` 把落在小块里的位置放到它前面或后面。显示用的 `NoteBody`、`InlineMd` 也画它；笔记的一行预览（Rust `notes::excerpt`）把它去掉。`:名字:`（没有 `pm-`）是网站的内容图标，Pomelo 不画。各家浏览器对这种小块的做法不一样，改了这里在 Safari 里跑一遍 `?mock&edtest=<端口>`（`testing.md`）。
- **图标库**（`shared/iconLibrary.tsx`）：`IconDialog`、`IconField`（弹窗里名字前的那一格）、`StoredIcon`。存成 `i:<键>`，键是图标的文件名；念念不忘以前用的 48 个键（`pin` 是地点、`notebook` 是带笔的本子…）原样留着，被它们占了名字的两个文件另起键（`pushpin`、`notebook-plain`）。Rust 只管长度（`common::clean_icon`），不认识的键只是不画。

## 界面外框

- **页签和前进后退**（`src/app/tabs.tsx`）：只在界面里：每个页签一串走过的页（最多 50 步），用路由地址记（`#/finance/assets`：模块的子页是地址的第二段，`subpage.ts`）。路由只显示当前页签的页，切页签就是换地址（页面重新打开）。索引签、模块坞、柚子瓣、全局搜索走 `open`（别的页签开着这个模块就切过去）；页面里自己的跳转照常，外框记下来。鼠标侧键用 `mouseup` 的第 4、5 键，也有 ⌘[ ⌘]。页签（各自当前那一页）存在 `settings` 的 `ui.tabs`，打开 App 时恢复。
- **模块坞**（`dock.ts`、`DockPage.tsx`）：分类和置顶存在 `settings` 的 `ui.dock`，按模块键记（建出来的是 `list/编号`、`progress/编号`），隐藏还用 `ui.module_hidden`（搜索和柚子也读它），都不进撤销。哪个分类都没有的模块（新加的、刚建的）放进它的默认分类。助手在导航里各是一个键（`translate`、`pub2md`、`seeker`），页面是柚子里原来的那几页，数据不动。柚子瓣（`Bloom.tsx`）是同一份设置的另一种画法（SVG），不另存；它一直挂着，编辑时只更新内容，不重新播展开的动画。拖动用鼠标事件（`drag.tsx`：落点用 `data-drop`、插在哪个前面用 `data-mod`，柚子瓣自己算落在哪一瓣）。实时小字是 Rust 的只读命令 `dock_live`（`dock.rs`）。
- **柚子**（`Pomelo.tsx`）：一个 SVG 组件，表情是参数，动画用 CSS（`frame.css`）。心情：今日简报（`brief.rs`）让模型在最后一行写「心情：…」，Rust 取出来存进 `briefs.mood`（正文不留），模拟模型给「很忙」（`?mock&mood=` 能换）；`youzi_brief` 带上写好的时间（`moodAt`，就是那一行的 `updated_at`），界面只在这之后一小时内用它，其余时候每小时从不负面的几个里随机挑。状态：柚子在写读 `youzi_status` 的 `generating`；出错由界面报（`reportProblem`）：每天的自动备份失败，发布和 Pub2MD 开始后登记一个检查（`watchJob`），外框每 2 秒问一次直到做完，离开那一页也照样报。
- **速记小窗**（`capture.rs`、`src/capture/`、`capture.html`）：同一个 App 的第二个窗口（`capture`），第一次按 ⌥Space 时才建，之后只是藏起来（每次重建要半秒多；藏着时页面也还在内存里，约几十 MB）。⌥Space 用 Tauri 官方的全局快捷键插件，只在运行时登记（开发版、测试版也会抢这个键；被占了就只能从菜单栏打开）。窗口浮在最上面、跨所有桌面、能盖在全屏 App 上（`FullScreenAuxiliary`）。呼出前记下最前面的 App，Esc / ⌘W / 关闭时还给它；点别处时页面收到 `capture-blur` 自己决定收不收（图钉、正在选文件时不收）。草稿是 `settings` 的 `capture.*`，页面随打随存（停 0.4 秒）、收起前再存一次；记下用自己的命令（建笔记或任务和清空草稿在同一个事务里，一步 ⌘Z）；「存为 .md」在页面里先把念念不忘的格式转成 Markdown（`lite.ts` 的 `liteMarkdown`：一行一段、列表连着、++下划线++ 写成 <u>），弹系统的存储框，再由 Rust 写文件、把草稿里的附件复制到旁边（同名的不覆盖，内容一样的用回原来那份），不进撤销、不碰草稿，然后发 `capture-saved` 让主窗口刷新（在小窗里确认柚子的卡片也发，`youzi_card_confirm` 看是哪个窗口调的）。问柚子（`CaptureChat.tsx`，第一次打开这一栏才加载柚子的 Markdown 那些）就是柚子自己的对话：`youzi_send` 带 `capture`，新对话私密、记进 youzi.db 偏好 `capture.chat`（同时只有一个，新的进来旧的删掉）；`library.rs` 的 `unlisted!()` 把它和 Rater 的复盘记录一起挡在对话列表、对话搜索、⌘K、索引和模块坞的对话数外面。「新对话」删掉它，「在 Pomelo 里继续对话」去掉偏好、取消私密，发 `capture-chat` 给主窗口去柚子页打开。翻译（`CaptureTranslate.tsx`）调 Translator 自己的命令，界面逻辑和 Translator 页共用 `translator.tsx`；窗口回到前面时重新读一遍（有没写完的输入就不读），两边才不会各拿各的。回答里的记录链接在小窗的内存路由里被接住，发 `capture-open` 给主窗口照全局搜索的方式打开。有对话时 `capture_fit` 把窗口拉到 560 高（顶边不动，出了屏幕就往上挪），回去时还原。
- **Mac 菜单栏**（`menu.rs`）：自己建的菜单，代替 Tauri 默认的那份（默认的 ⌘W 是关窗口）。页签相关的菜单项发 `app-menu` 给主窗口，由 `App.tsx` 的 `useTabKeys` 照页签和索引签做；焦点在速记小窗时只认 ⌘W / ⇧⌘W（收起）。⌘1～⌘9 那几行的名字由页面在置顶变了时发过来（`app_menu_index`），Rust 重建菜单。⌘⇧[ ⌘⇧] 只在页面里认。

## 模块之间

一个操作要改好几张表时放在一个事务里（可以嵌套，模块互相调用、导入时调用各模块都不冲突），中途出错就全部不算。

- **一网打尽**（`modules/bookmarks.rs`）：文件夹和网址一张表，界面拿整张表自己搭树。网站图标在 `icons.rs`：页面问「有哪些图标」时把缓存的（数据目录 `icons/`）转成 data URL 一起给，同时在后台给还没有图标的网站去取（一次 4 个；先读首页的 `<link rel="icon">`，再试 favicon 的几个常见位置，子域名都没有就试主站；只认真的图片，最大 300 KB），取到了发 `bookmark-icons` 让页面刷新；取不到的记进 `failed.json`，7 天后再试。只有正式数据目录的打包版会去取，开发版、测试、临时数据目录都不联网。首页、搜索、柚子读它都照别的模块（`home.rs`、`search/sources.rs`、`data.rs` 的 `pomelo_bookmarks`）。
- **五花八门、循序渐进**：建出来的每一个当一个模块，键是 `list/编号` 或 `progress/编号`（也是页面地址）；导航里的位置、隐藏、「发给云端」、循序渐进的类型列表（`kinds` 表里 `module` 就是这个键，和随意画画的类型同一套）都按键存，所以编号永远不重用。单选、多选的选项和循序渐进的类型按在列表里的位置配颜色（`--tag-1`～`--tag-8`，超过 8 个从头再来），只是显示，不存。界面的模块列表 = 固定模块 + 从 Rust 读到的建出来的模块。五花八门每条的字段值存成一份 JSON，规则都在 `lists.rs` 里检查；排序、筛选只是页面上的显示。柚子用两个工具（`pomelo_lists`、`pomelo_progress`）查它们，工具说明里不写模块名（不带个人数据）。
- **导入账单**：分两块。账单和行在 `modules/finance/import.rs`（`pomelo.db`，进撤销和导出）：每个文件一批（`fin_imports`），每行留读到的原文（`source_json`）和我核对后的草稿（`draft_json`），确认后才写进 `fin_entries`（一步撤销）；候选没决定的 Rust 挡着不让入账。读账单的是助手 **Importer**（`youzi/assistants/importer.rs`，细则在它开头）：只用柚子的云端模型（`schedule::route`；本地模型看不了图），三个命令，模型只能走这几步，全部结果都等我入账：
  - `youzi_importer_extract`：Excel 用 `calamine` 转成带行号的文字（每 60 行一块，带表头），PDF 用 PDFKit 画成图（每 4 页一块），截图原样发；每一行单独检查，不合格的值不用、记成疑点；模型漏掉的「像交易的行」再问一次，还没有就留一行；全局同时最多 4 个请求。
  - `youzi_importer_match`：查重：发这些行和前后 7 天的账本；模型说合并时，程序还要查金额、币种、日期、付款渠道（`CHANNELS`，要加渠道在这里加一行）和分类，对不上的变成「拿不准」列进候选（合并会藏起一笔钱，这里程序把关）。
  - `youzi_importer_tidy`：再整理：把没保存过的行发给模型，再查一遍重。查重和再整理写之前逐行比对，运行期间我动过的行不写。
  - 提示词清单和模型在 `youzi.db` 偏好 `assistant.importer`；页面上的任务放在 `importJob.ts`，离开页面也跑完。
- **笔记转待办**：任务记下来自哪条笔记（笔记删了变空）；数据文件里用笔记的记录时间对上，导入时先导笔记再导待办。柚子「转为待办」：模型自己判断有几件、每张卡片怎么写（字段同一句话填好的任务，位置是模型挑的），Rust 一张张检查过再列出来；勾选后整组交给 `todo_tasks_from_note`，照任务面板的规则逐张建、一步 ⌘Z（有一张不合规矩整步不做）。

## 搜索和索引

- **全局搜索**（按字）：Rust 在 SQLite 里逐条比对每个模块要搜的字段（中英文都能找到词中间的字），每个词都出现才算，每类最多 6 条。界面跳到那个模块，由模块页面打开那条记录（`src/shared/open.ts`）。
- **一个入口**：`search/query.rs`，「意思相近」和柚子的搜索都调它。给它一句话、范围和方式（按字、按意思、合并），返回记录在哪、标题、片段、得分和怎么找到的。芝麻开门不进索引；隐藏的模块、云端规则在这里挡。向量或重排服务用不了时照样按字返回。
- **三种方式**：按字用 FTS5（中文两个字一组）；按意思把问题和记录都算成向量比相似度；合并是两种名次合在一起，再用重排模型给前 30 条打分：有把握的（0.1 分以上）排前面，其余保持合并后的顺序（「找房子」这种短词它对什么都给接近 0 分，全按它排会把对的挤下去）。
- **索引和原始数据分开**：`search.db` 只放算出来的东西（每条记录要搜的文字、指纹、全文索引和向量，项目资料、记忆、知识库的分段和向量）；「哪些要建索引」这类选择留在 `youzi.db`。
- **后台更新**（`search/indexer.rs`）：用自己的只读连接，每 2 秒看一眼两个数据库有没有被改过（SQLite 的 `data_version`，撤销、导入、恢复都算），有就按指纹比对，只写变了的、删掉没了的。不用在每个命令里挂钩子。
- **向量什么时候算**：只在向量服务本来开着、或按意思搜 / 柚子检索要用时补算，不为改一条记录专门启动服务。重建（`search.db` 新建、换向量模型、换文字规则）例外：自动启动服务，在后台从新到旧算完，期间照常按字找。
- **速度**：向量压成 8 位整数载入内存逐条比（20 万段约 200 MB）；20 万条实测按字约 0.06 秒、按意思约 0.02 秒。再大就换近似检索，所以向量检索做成了能换的部件。
- **全量读取**：年度总结这类要看全部数据的任务不经过检索，直接用各模块的只读函数读全。

## 呦呦漫游（个人网站）

- **内容只在网站文件夹里**：`site.folder` 记位置（默认 `~/Documents/GitHub/personal-website`），不存副本，不进 `pomelo.db`、备份、导出、撤销和搜索；网站的 git 历史就是它的历史。内容格式照它的 `content.config.ts` 和现有文件。
- **运行方式**（`site/mod.rs`，同柚子）：只有正式数据目录的打包版（或 `POMELO_REAL_SITE=1`）用真文件夹、真推 GitHub、用 gh 读 Vercel；其余用数据目录里的副本（`site-sandbox/website`，APFS 复制）和本机的假远端（`site-sandbox/remote.git`），上线结果是模拟的；远端不是本机文件夹时一律不提交、不推送。
- **外部程序**：`/usr/bin/git`（推送靠钥匙串里已有的 git 凭据，要密码就报错、不卡住）；gh 只读上线结果；Node 按网站的 `.nvmrc` 在 nvm 里找。缺哪个只关掉用它的功能，写明原因。
- **本地服务**：`npm run dev` 在自己的进程组里跑（正式 4328，副本 4338），退出 Pomelo 时整组停掉；端口上已有别处启动的就直接用、不停它。启动时设 `ASTRO_DEV_BACKGROUND`，让 Astro 留在前台。
- **发布**（`publish.rs`，后台任务）：fetch 只快进（分叉、冲突、不在 `main` 都停）→ 确认框带着改动的指纹 → `npm run qa`（最多 15 分钟，没过留最后几十行输出）→ 再确认没落后、指纹还对，`git add -A`、commit（文字原样）、`push origin main`，不强推、不改历史 → 每 8 秒用 `gh api` 读 Vercel 状态，15 分钟没结果写「没等到」。改动清单（`changes.rs`）是 `git status` 加还没推的提交，按路径认出是哪类内容。
- **读写内容**（`yaml.rs`、`doc.rs`）：读用 `yaml-rust2`（键保持顺序）；写是 js-yaml 4.3 `dump` 的逐行移植（网站原有文件就是它写的），JSON 照 `JSON.stringify(…, null, 2)`。键原地改、不认识的原样留、没变的文件不写、写之前比对读进来时的指纹。85 组对照测试，另有只读测试拿网站全部内容文件和 Node 跑的 js-yaml 逐字比对。各页各一个文件（`wander.rs` `now.rs` `about.rs` `career.rs` `terms.rs`）。
- **资源库**（`images.rs`、`registry.rs`）：内容只写引用，保存时检查引用的是资源库里的文件。加文件都走 `site_files_add`：超过 1.5 MB 的图片用 `sips` 转 JPEG、缩长边；资源库里有一模一样的就用它，网站别处有一样的就拒绝；否则存进资源库并按去处自动登记。删之前照网站 `asset-reference-report.mjs` 的规则扫引用。界面经 `pomelo-site://localhost/<网址>` 显示网站里的图片（只认 `public/` 下的）。
- **预览和编辑器**：Rust 开一个 `site-preview` 窗口装本地服务的那一页（它不能调用 Pomelo 的命令）；编辑器 `MdEditor.tsx` 是共用输入框（见「写字的输入框」）的 Markdown Flavor。

- **Pomelo 不存画布**：`canvas.rs` 只记文件夹（设置 `canvas.folder`，默认 `~/Documents/GitHub/visual-atelier`）和上次看的那块（`canvas.last`）；不进 `pomelo.db` 的表、备份、导出、撤销、搜索，柚子不读。

## Atlas

- **数据在 Rust**（`youzi/atlas.rs`）：每次年度总结写完信，存一份「呈现结果」：Rust 数好的数字和记录的快照，加同一个模型给各幕写的话。每运行一次多一行（`year_atlas`），就是历史。补做某一年、立即运行都走年度总结那个定时任务的流程和模型（`schedule.rs` 的 `atlas_run`）。
- **画在设计里**：设计是 visual-atelier 冻结的快照，一份一个文件（`src/vendor/pomelo/atlas/<名字>-<版本>/design.js`，同步来的，不手改）。Rust 的 `DESIGN` 是新写的那一份记的设计；每一行记着自己的，打开时照它记的那一版画（`modules/atlas/designs.ts` 按名字和版本找，打开小报时才加载）。出了新设计：同步新的快照、改 `DESIGN`，旧的快照留着。
- **小报放在一个 frame 里**（`Journey.tsx`）：frame 的文档是快照自己带的（样式、上墨的脚本都是冻结那天的），所以外面的样式进不来、里面的出不去，旧的小报不会被后来的界面改动弄坏。同一个来源，页面直接把数据交给它，它把「在模块里打开」「收进抽屉」「Esc」告诉页面。
- **模型只做三件事**：给每一幕写一两句话、挑要引用的记录、把聊天的话题归类。数字、日期、图、用哪个泡泡都不归它；它写的东西 Rust 都照快照查一遍，不认识的丢掉。
- **删除只在页上**：`atlas_delete`（进撤销）。没有删它的 AI 工具，定时任务也不删。

## 首页和每天的例行检查

- **首页**：数字和清单由 `home.rs` 每次打开时现算（只读，不存东西），隐藏的模块不算；今天的待办直接用一步一步的列表。
- **例行检查**：每天第一次打开 App、或开着过了零点，做三件事：每日备份；把时间段结束或已经打满的打卡任务标为完成；记上到日子的固定支出（漏掉的一起补）。窗口关着、只留菜单栏时，每日备份每 5 分钟检查一次，另外两件等下次打开窗口补上。这些不进撤销（撤销了下次还会再做）。

## 图表

回看、钱来钱往和首页的图表是自己用 SVG 画的（柱状图、折线、圆环、排行条、预算条），不引入图表库。颜色是一套检查过色弱可读性的固定顺序，深浅模式各一套；每张图旁边都有对应的数字或清单。

App 本体约 7 MB，运行内存约 85 MB；导入全部现有数据后 `pomelo.db` 约 0.5 MB，十年也在几百 MB 以内。真正占空间的是附件。

## 柚子（AI）

- **Atlas 的底子**（`atlas.rs`）：年度总结的信写完，Rust 先存一份当时能读的数字和记录的快照，再让同一个模型只写各幕的话、挑记录编号（数字、日期都是 Rust 的），检查过存进 `year_atlas`；这一步失败不影响信。模型的回复照宽了读（`parse`：前后带别的字、话里的英文双引号、多余的逗号、按幕的名字给都认），读不出来就告诉它原因再要，一共三次（`ask`）；思考算在回复长度里，关不掉思考的云端模型（GLM、GPT）每次都留足思考的余量，后两次让它尽量少想。首页的「那年今日」在 `home.rs`。
- **名字**：界面、提示词、文档都叫柚子；代码、文件名、偏好键、页面地址 `#/youzi` 用 youzi。旧名（小拾、代码里的 picky）已在升级时换掉（迁移见 `schema.md` 的版本记录，文件夹改名在 `youzi/store.rs` 的 `adopt_old_names`）；数据文件 38 之前的 `picky` 照样读；聊天记录里的「小拾」不动。
- **同时生成**（`chat.rs` 的 `Runs`）：每个对话一个生成位置，对话、定时任务、助手、简报各写各的。本地模型一次答一个（`--parallel 1`），请求在 `provider.rs` 排队；云端不排队。云端还没收到内容时遇到 429、5xx、流里的错误或连不上，等 2 / 5 / 10 秒（照 `Retry-After`，最多 20 秒）重发，最多 3 次。本地模型在回答时不能停、不能换别的本地模型。
- **柚子服务**：一个统一的「发消息、流式收回复」接口，背后是本地模型（8080，OpenAI 兼容）或六家云端（只连固定的官方 HTTPS 地址；Anthropic 用它的 Messages 接口，其余是 OpenAI 那种）。回复、思考、用量边收边交给界面，定时存进 `youzi.db`，中断时保存已收到的；出错只显示固定的中文提示。
- **思考**：每次调用都说要不要思考，只有「能开关」的模型收到开关，要思考的多留回复长度（`Route::with_thinking`）。模型不收某个设置就去掉再发一次，并记住到退出；阿里云的内容审核拦下时直接这样说，不重试。查数据的那几轮按各家要求原样发回思考内容（签名等），以前的问答只发文字。
- **思考强度**：只有一个入口，`provider.rs` 的 `level_for`（`stream` 开头）：请求选的强度模型有就用，否则用模型固定的默认，再没有就不发；高强度时在短的回复上限上加余量（`Options.room_fixed`：调用方算过了就不加）。所以没选强度的调用都不用改。词原样发给接口，400 就去掉再问一次并记住（`模型#词`）。能选的地方存「开关 + 强度」：`sessions`、`schedules`、偏好 `brief.effort`、`assistant.translate`、`rater.options`、Seeker 的 `options`；Pub2MD、Importer、面板帮手（偏好 `assist.model` 模型、`assist.level` 思考）存 `cloud::Level`。界面都由 `Thinking.tsx` 按当前模型列选项（`ThinkingButton`、`LevelPicker`，助手设置页的 `ModelRow.tsx`）。**中间步骤**（对话压缩、读长文件、年度总结的每月阅读）不传强度，用模型的默认，只有最后的回答用选的。Pub2MD 查术语直接连接口的几条路（`search.rs`）照 `CloudModel::effort`。
- **本地模型**：读 `~/Documents/LLM/config/models.json`（聊天、向量、重排三类），用 `llmctl.sh` 启停，查 `/health` 判断状态。聊天模型同一时间一个（8080），向量（8081）、重排（8082）要用时自动启动；柚子启动的闲置 30 分钟后停、退出柚儿园时停，别处启动的不碰。上下文按名字里的大小限制。这些控制只给界面和菜单栏，不交给 AI。
- **数据**：`youzi.db` 存对话、消息版本树、调用记录、附件和分段文字、模板、预设、摘要、记忆、项目资料、出处、卡片、定时任务、简报、知识库的选择（表见[数据结构](schema.md)）；分段和向量在 `search.db`；文件副本在 `youzi-files/`。
- **读文件**（`files.rs`、`office.rs`、`reading.rs`）：添加时读一次存成分段文字。表格用 `calamine`、CSV 自己解析，大表格只存表头和前 50 行（「查表」每次从副本现读整张）；网页在 Rust 里下载（20 秒、5 MB 以内）取正文成 Markdown；图片不存文字，发给云端前在临时文件夹里用 `sips` 缩小；没有文字的 PDF（扫描件）、只有图片的 Word / PowerPoint 当附件时存一句「没有文字、共几页 / 几张图」（`prepare` 里，知识库照旧当扫描件只认文件名），云端模型用读文件的 `look` 看。追问时前面问题的附件另起一段，标成「前面附过」。
- **挑选和检索**：记忆和资料段落先按向量相似度取一批（记忆 12 条、资料 20 段，0.30 以上），再用重排模型挑出至多 6 条；重排用不了就只按相似度（0.35 以上）。知识库同样。
- **出处**（`cite.rs`）：一次回复拿到的东西统一编号（同一条记录一个号），随回复存进 `youzi.db`；私密对话不在结果里；「读整条」读之前再按能读和云端的规则查一遍。
- **查数据**（`data.rs`）：用模型的工具调用。Rust 定义每个模块的只读查询（统计和页面共用一个函数），先检查能不能读、这次能不能发给云端，再查、截短后交回；钱来钱往按两块算云端（`cloud_key`：资产 = 账户、余额、持仓，其余是收支），查询、页面、卡片、搜索结果都按自己那块挡，偏好里旧的「钱来钱往」开关当资产的；一次回答最多 4 轮，查到的存进 `youzi.db`。小窗只告诉 Rust 当前页面和记录编号，内容由 Rust 按同样的规则取。
- **改数据**（`act/`）：七个模块共 14 个写数据的工具，模型只能「提议」：Rust 读它给的字段（日期词按今天算、名称对上已有的），按名称里的字去找要改的那条（几条就都列出来让我选），用模块自己的函数在最后撤回的事务里试写一遍，前后一比就是卡片；告诉模型的话照抄卡片。查数据的 4 轮之后还有一轮只给写数据的工具。确认时 Rust 按卡片里存的写入，整张一步 ⌘Z。隐藏的模块不给工具；云端不允许的模块一律拒绝。还没确认的卡片能改：每一条有个编号（第几条回复的第几条），工具结果里告诉模型，前面回复里还没确认的卡片列在说明里（只列这个模型能看的模块）；模型用同一个工具加 `replace`（编号）重新提议，Rust 照样检查、试写后把那一条换掉（这条回复的或前面的，只限这个对话当前显示的分支）。新书影先用书单 / 影单检索补作者、国家、类型；模型自己说了作者而查到的是别人时，算查到了同名的另一部，用模型自己的。
- **问我（ASK，`ask.rs`）**：工具 `pomelo_ask_user`，只在云端模型的对话里提供（`chat.rs` 的 `generate` 判断，定时任务和复盘记录不给）。模型调用后，卡片存进 `run_asks`、发给页面，这条回答的后台任务停在 `ask::Gate`（一个 oneshot）上，不发任何请求；`youzi_ask_answer` 记下回答、把文字交回去，变成工具结果，循环接着走（只问了我的一轮不算查数据的轮数，问题不合格的算，免得停不下来）。这期间对话的位置一直占着，所以输入框发不了。停止时任务被结束、卡片改成没回答。退出时回答记成中断、卡片留着；之后回答时已没有任务在等，命令返回 `followUp`，页面把它当新消息发出，这样不用保存模型工作的中间状态。在这个对话里开始新的回答时，留下的卡片关掉。
- **润色、补全、一句话填好 / 改好**（`assist.rs`）：一问一答，模型和思考照「设置 → 柚子」的「面板帮手」（默认柚子现在选的、思考 · 模型的默认）；Rust 写好提示（一句话填好附上今天前后的日历和已有的分类、分组、渠道、模板；改好再附上这条记录现在的样子，用 `data.rs` 的 `record_text`，界面只传记录编号），把回答读成字段再检查一遍才交给面板（日期真实、名字对上、重复规则按 `todo.rs` 的 `Rule` 能读、链接得是句子里写了的；改好时什么都不补默认值，`clear` 只收这个模块能清空的几项），保存照常走各模块的命令。呦呦漫游在 `data.rs` 里是「只帮忙、不读」的模块（`HELP_ONLY`）。
- **插件库**（`skills/`）：开着、Key 齐了、并且「自己决定用」或这一条点名要它，才给模型这个工具；点名要的在系统消息里写明必须先用，点名联网的 Rust 先拿问题本身搜一次。不用 `tool_choice: required`（有的服务不认）。查到的都编号成出处、记进「查了」。
  - **联网**（`web.rs`）调 Tavily 的固定地址。**书单 / 影单检索**（`works.rs`）：先用 Wikidata 找到这一部，再按编号去 Open Library、TMDb、Jikan 核对；Wikidata 排队、每次隔 0.35 秒，请求头带联系邮箱；查到的在内存里留 6 小时。
  - **读文件**、**查知识库**由 `chat.rs` 执行，只在有东西可读时给。资料放不下时不再分段阅读：发每个文件的目录和按问题挑出的段落（最多 8 段，每个文件至少给第一段），读到的段落编号成出处。
- **定时**（`schedule.rs`）：后台循环每 30 秒看一次到点的任务，跑的时候和发消息走同一条路，只是只读、系统消息说明我不在。要用的本地模型没运行就先启动，跑完只停它自己启动的。「上次跑到哪」放在单独的表里，不进撤销。
- **今日简报**（`brief.rs`）：Rust 先用 `data.rs` 读好待办、该提醒的日子、投递、最近两周的笔记（每块有上限；每条笔记带「几天前」，末尾写最近一条哪天记、之后有没有再记），一次请求（系统消息是提示词：偏好 `brief.prompt`，空就用程序里的 `DEFAULT_PROMPT`；日期和读到的数据放在用户消息里），最多等 5 分钟；不占对话的生成位置。
- **年度总结**（`yearly.rs`）：不用查数据的工具，Rust 先读好全年和算好的数字（含去年同期的数字和差值、去年的年度总结）。放得下就一次发；放不下就按月整理要点（存进 `month_summaries`，读的内容没变就直接用），再拿要点写全年。写的是哪一年记在 `year_runs`。「定时」里画的流程图是 `yearly.rs` 的 `FLOW`（和插件库的 `Flow` 同一种），改了流程要一起改。
- **知识库**（`knowledge.rs`）：`youzi.db` 只记库、文件夹、网页正文、云端开关和对话、项目选的库，都能撤销；文件清单、分段和向量在 `search.db`（后台扫描只写它，不挡 ⌘Z）。不监听文件：打开柚子页、打开知识库对话框和每 10 分钟比一遍大小和修改时间；建索引一次一个，文字没变的段落沿用旧向量。「打开文件」先检查路径没出文件夹。
- **助手**（`assistants/`）：设置和上一次的结果放在 `youzi.db` 偏好（`assistant.<名字>`），不进撤销和导出。**Importer** 见上面「导入账单」。**Translator**（`translate.rs`）：Rust 拼提示词；长文按段切块依次流式翻，后一块带上前一块译文的结尾（300 字以内）对齐译法；在后台任务里跑，结果每秒存一次、页面轮询，离开、刷新都不丢。**呦呦漫游 · 按中文起草**（`site.rs`）用同一套 `translate_with`，结果只在内存。
- **Pub2MD**（`assistants/pub2md/`，流程在 `job.rs`）：
  - **提取**：直连 Mathpix（手写 multipart 上传，要分页标记、不让它拿去改进；pdf_id 一拿到就存，同样的文件用上次的原始结果）。原页图用 PDFKit 画成长边 1568 的 JPEG；图片先用 NSImage 合成 PDF（认 EXIF 方向）。
  - **切块和流程**：`mmd.rs` 认出页、能切的地方和论文各部分，`chunk.rs` 切草案、纠正 Supervisor 不合规矩的改动；每块的下一步由 `job.rs` 排，JoinSet 同时做几块，术语表没好之前不翻；每一步存进 `.pub2md/job.json`，「继续」从那里接着做。
  - **检查和修补**：`check.rs` 只比文字（细则在它开头），`prompts.rs` 修模型常出的小毛病；回复被思考占满时多留长度再试一次；请求失败、内容审核按需求里的规则换备用模型。Supervisor 的 JSON 读不了先补没转义的引号，术语表截断时取完整的条目；回答长度按思考强度多留（低 8K、中 16K、高 32K）。
  - **联网查术语**（`search.rs`）：各家自带的搜索（DeepSeek Search / Fetch、Aliyun `enable_search`、OpenAI `web_search`、Anthropic web_search / web_fetch、Google `google_search`），其余用 Tavily。简繁用 `script.rs`（ferrous-opencc，s2twp / tw2sp，跳过代码、链接和网址）。
  - **另存为**：Mathpix `/v3/converter`，图片换回提取时记下的 Mathpix 链接（30 天内有效）。
  - **预览**：mathpix-markdown-it 浏览器版（单独打包，打开预览才加载），放进不能跑脚本的 `sandbox` iframe；提示词页的说明和真正发出的用同一套函数拼。
  - 页面命令都是 `async`，先取完数据库和钥匙串再拿排队的锁；「删除」只删 Pub2MD 建的文件夹，移到废纸篓。设置和最近 10 份在 `youzi.db` 偏好，排队的只在内存；模拟版用 PDFKit 读出的文字代替 Mathpix。
- **Work**（`work.rs`、`word.rs`、`skills/toolbox.rs`）：「保存为 Word」把回答写成自己生成的 .docx（真正的标题、列表、表格、引用、代码样式，出处列在文末），只在你点了以后、在你选的文件夹里新建，不覆盖。改文件只能改 Rust 列出的文件（附件的原文件、旧问题选的文件、知识库里的文件），读成编号的段落；模型的提议逐段检查后放进卡片（一条回复一个文件，记下文件的指纹），写入时文件变了就不写；Word 只改变了的字，其余一个字节都不动，改不了的拒绝（细则在 `word.rs` 开头）。
- **Excel 工具箱**（`excel.rs`，不加新库，zip + quick-xml；calamine 只读）：读整个 .xlsx，只重写动到的表：没改的格子保留原来的 XML，别的部分原样复制；文字写成内联字符串，不碰共享字符串。一次提议里的行号都按读到的算：先改格子，再从下往上加删行，挪动时重写所有表的公式（`rewrite` 认 A1 引用、范围、整行整列、Sheet!引用，跳过字符串、函数名和结构化引用）、合并格、条件格式、数据验证、超链接、筛选、定义的名称，共享公式先展开。挪不好的（图表、表格对象、批注、透视表、跨几张表的公式）直接拒绝。和 Excel 不同的一处：加在一个范围最后一行后面、而公式在这几行外面时（合计在明细下面），范围扩到新行（`grows`）；提议的公式用到自己所在的格子不收（`names_itself`）。写入时去掉 calcChain.xml、要求打开时全部重算。读大文件在数据库锁外（`excel_plan`，再 `excel_commit` 放进卡片）。
- **定时任务的工具**（`chat.rs` 的 `read_only`，`lookup_plan`）：不给写 Pomelo 数据的工具和题库；给工具箱（卡片按 `run_id` 存，留在那次对话里）；联网搜索不看「自己决定用」（`Ctx.scheduled`），开着、有 Key 就给。
- **看文档里的图片**（`office.rs`）：Word、PowerPoint 从 zip 里按文档顺序取图（`relations` 对上图片文件，用附近的文字或页码说明在哪）；PDF 用 Quartz 的 PDF 对象数每页的图（`pdf.rs` 的 `image_pages`，PDFKit 不给这个），看的时候用 PDFKit 画整页。读文件的 `images`、`look` 在 `chat.rs` 的 `file_images`，查知识库的在 `knowledge.rs`，都在数据库锁外读文件、只给云端模型、一个回答共用 8 张的上限，图片跟在这一轮的结果后面发。
- **DevJanitor**（`assistants/janitor/`，电脑管家）：
  - **运行方式**：只有正式数据目录的打包版扫真磁盘、真的删；开发版、测试、设了 `POMELO_DATA_DIR` 的打包版扫数据目录里的「假 Mac」（`fake.rs` 造的，大文件是稀疏文件、几乎不占地方，`.janitor-fake.json` 写着假的磁盘大小、在跑的程序、Docker），删除和废纸篓都在里面，`conda clean` 不真跑。
  - **扫描**（`scan.rs`）：8 个线程一起走一遍（App、个人文件夹、/Users/Shared、资源库、/opt、/usr/local），只看名字、大小、时间：不跨到别的磁盘、不跟替身、不进 App 包里找单个文件。走的时候顺手认出一键清理的条目（项目文件夹看旁边有没有 package.json、Cargo.toml 这类标记）、装着的 App、资源库里可能是残留的条目、10 MB 以上的文件；走完自下往上算每个文件夹多大、项目最近一次改文件的时间（不算依赖、编译结果和 .git）。硬链接按 (设备, inode) 只算一次，一个条目里的文件所有链接都在它里面才算「删了能腾出」。重复文件先按大小分组，再比头尾 64 KB，最后整个读一遍比。真磁盘约 135 万个文件、17 秒。
  - **结果**（`store.rs`）：只存 20 MB 以上的文件夹和文件给环形图，一个文件夹里没存的部分算「其余」。一次扫完整个换掉，页面一直看到上一次的。清理后去掉条目、从上面各层减掉腾出的大小。
  - **系统**（`system.rs`，不加新依赖）：磁盘总数用 `df`；在跑的开发工具用 `ps` 和 `lsof` 看它们的工作文件夹（判断「在用」，删之前再看一次）；App 的编号用 `plutil` 读 Info.plist；很久没打开用 Spotlight 的 `mdls`；Docker 用 `docker system df`（没开就只有文件夹大小）；完全磁盘访问权限看 TCC.db 能不能打开，没给时不进要权限的那些文件夹（不弹授权框）；内存用 `sysctl`、`vm_stat` 和 libproc 的 footprint（同活动监视器）。移到废纸篓用 Pub2MD 那段 NSFileManager。
  - **开发环境**（`env.rs`）：扫描走完后接着认：大小从走过的整棵树取（`scan.rs` 的 `Tree`，按路径找文件夹），版本和默认读环境自己的小文件（JDK 的 `release`、`conda-meta/`、`pyvenv.cfg`、nvm 的 `alias/default`、rustup 的 `settings.toml`、Homebrew 的 `Cellar/` 和 `bin/python3` 指向哪），真磁盘上再问 `java_home`、`xcode-select`、`plutil`（App 的版本）和 `docker`（开着时的镜像、容器、数据卷）。每个认出来的环境「认领」自己的文件夹，剩下的点开头的文件夹、`~/.cache`、`~/.local/share`、`/opt`、`/usr/local` 里没人认领、还有 100 MB 以上的进「其他」。结果和扫描一起存进 `janitor.db`。
  - **Agent**（`agent.rs`）：借柚子的对话（私密，偏好 `janitor.chat` 记着是哪个；「新对话」先建新行再删旧行，编号才不会被重用，页面按编号切换），走柚子同一条生成的路：`chat.rs` 的 `prepare` 换成 DevJanitor 的模型，`generate` 在系统消息里接上 SKILL 和扫描的情况（`agent::system`），工具换成 DevJanitor 自己的（`janitor_plan`：看、跑只读命令、三种提议，加上开着的联网搜索和云端模型的问我，不给柚儿园的数据），最多查 12 轮（`Request.rounds`）。
    - 只读命令（`readonly.rs`）：一份程序列表和各自只读的子命令、参数，有管道、重定向、`$`、括号的不认，过了检查才用 `zsh -lic` 跑（60 秒停、输出最多 6 万字），结果当作一次查询回给模型。
    - 卡片：提议在数据库锁外检查好（路径、大小、受保护、sudo、规则的范围），存进 `janitor_cards`，每次成功都发给页面（`StreamEvent::Janitor`），所以写的时候就看得到；点过的由 `agent::in_history` 写成「卡片的结果」，下一问一起发。
    - 执行：移到废纸篓和扫描一样走 `Sys`；命令在后台线程里用 `zsh -lic` 从个人文件夹跑（自己一个进程组，「停下」整组结束），结束时把最后一段输出存进卡片；假 Mac 不跑命令。加规则一步撤销，扫描时按名字一层层对路径，对上的就是一键清理的条目（`rule:编号` 一类）。
  - **柚子查 DevJanitor**：「发给云端」里多一行 DevJanitor（默认能发，和呦呦漫游一样只是开关），没隐藏、云端允许时柚子多一个只读工具 `pomelo_janitor_info`（磁盘和能清多少、开发环境），和 Agent 看的是同一份文字。
  - **受保护的地方**只在 `rules.rs` 的 `Protected` 写一份：一键清理认条目时跳过，清理前再查一次；只列出来的条目标出来，页面确认两次才移走。页面只传条目编号，路径从 `janitor.db` 取。

- **云端 Key**：只在钥匙串（和插件库的 Key 同一组），界面只显示「已保存」；不进数据库、备份、导出和日志。钥匙串里只有一项（服务名「Pomelo OS Agent」，改了就读不到存过的 Key），所有 Key 存在里面；App 打开时读一次、放在内存里，查「有没有存」从不弹框。旧版一个 Key 一项的，新版第一次打开时读过来（每项弹一次，最后一次）再删掉，删不掉的在钥匙串访问里手动删。
- **空间管理**：算数据库和 `youzi-files/` 的大小，列出每份副本被谁用着；删副本只删文件、留下记录（「文件已删除」）。
- **开机自动启动**（`autostart.rs`）：Tauri 的 autostart 插件写一个带 `--hidden` 的 LaunchAgent，不用 AppleScript。带 `--hidden` 打开时，窗口第一次画出来之前就藏起来。开关存在设置里（默认开），每次打开时让登录项跟着开关；只有正式数据目录的打包版会登记。
- **Seeker**（`assistants/seeker.rs`、`seeker/`）：资料、草稿、导出记录都在 `youzi.db`，不存整份简历的副本。页面打字停一下自动存（`seekerDraft.ts` 排队，结构操作前先存完），每次保存一步撤销。导入只读 `transfer/` 认得的 Markdown，按「来源（文件#标题:第几个）」对上以前导入的。发给模型的资料在 `model.rs` 的 `context` 现拼；规则是「标题 + 分点」（`catalog.rs` 的 `rules_markdown`，Rater 也用），旧规则正文读出来时转成分点（`normalize`），下次保存才换。模型每次只调一次、没有工具；模型和思考按功能选（`catalog.rs` 的 `Settings::of`，没单独选的跟默认；以前的选材、审查模型读出来时转过来：`StoredSettings`）。选材和润色一条素材的回答按编号检查后给差异，确认才写；审查、润色要点、Summary 的回答变成批注（`notes_from`），调用结束时 Rust 自己存进草稿（一步撤销），页面关了也不丢；发给模型的草稿带短编号（`outline`：S1、E1、P1），对不上的那条略过。页面的调用放在 `seekerJobs.tsx`（不跟着页面卸载）。开发版打不开真的 Seeker 文件夹（`output.rs` 的 `allowed_path`）。岗位关联、「做简历」、公司资料都先读 `pomelo.db` 再锁 `youzi.db`，不嵌套。
- **Seeker 的 Word**（`word.rs`、`seeker/output.rs`）：模板编进 App（`src-tauri/templates/`，`scripts/resume-templates.ts` 生成，只留格式，生成后查一遍有没有个人文字），样板段落的位置写死在 `SLOTS_CN` / `SLOTS_EN`。导出照样板段落的格式、制表位和每栏字体一段段写，纸张、样式、编号原样，去掉缩略图；不数页数，只新建文件，存好用 Word 打开。英文和中文同一套，经历抬头写法不同，多 Summary 和空行。
- **Seeker 的两种语言**：每条资料记语言（事实、档案、网申总是共用；规则、豁免情况可以共用），草稿每种语言一行；每个命令都带语言，只动那一种。当前语言记在设置里（不进撤销），投石问路的「做简历」照它。
- **公司资料**（`seeker/company.rs`）：`knowledge/` 由我点一次加进知识库「Seeker」，之后和别的知识库文件夹一样原地读。公司名单每次现读（文件夹，加上招聘索引.md 给的中文名）。选材、审查时按岗位找到公司文件夹，用 `knowledge::retrieve_under` 按 JD 取至多 6 段放进系统提示。

- **岗位用的简历**（`seeker/output.rs`）：`youzi.db` 按文件路径记，关联只认 `cv/` 里的简历，一步撤销。投石问路原来的「简历」一栏开机时搬一次（`adopt_job_resumes`，不进撤销）。
- **规则发给谁**：哪个功能读哪几组规则只写一处（Seeker `model.rs` 的 `reads` / `task_of`，Rater `qbank::reads`、`practice::READS`、`interview::PREP_READS` / `SUMMARY_READS`、`record::READS`），真正调用和规则页的「发给」「发给模型的说明」都用它（`previews`）。每个功能的说明开头是 `model.rs` 的 `PRINCIPLES`。分组改名：程序自带的组只在 `seeker_groups` 记显示的名字，自己建的组改条目的类别。

- **Rater**（`assistants/rater.rs`）：题目一条一行（JSON），保存按版本号查、旧的进历史、一步撤销；秒数读的时候用同一个函数算。规则不另存，就是 Seeker 资料里 Rater 用途的规则；程序自带的几条（`qbank.rs` 的 `builtins`）不存，拼说明时组里没有能顶替的就加上（`group_rules`）。模型和思考按功能选（`qbank.rs` 的 `Options`、`chosen_model`，没单独选的跟默认），存在偏好，不进撤销。
- **三个题库 SKILL**（`rater/qbank.rs`，对话里是 `skills/qbank.rs`）：一次只调一次 Rater 的模型，没有工具；Rust 拼好资料，模型回 JSON，Rust 按编号查素材、改自哪道、去掉重复的，再交给页面或确认卡片；写进题库是我点的。对话里题放进确认卡片（`act/card.rs` 的 `add_rater`），确认时 Pomelo 的记录先写，Rater 的题后写。没确认的题，模型加 `replace` 和我的话，用同一套 SKILL 重写答案。
