# 验证方法

> 怎么测、用什么命令。原则在 CLAUDE.md：平时只用模拟的模型和编的数据；真模型、真接口、要花钱的先问我；绝不碰真实数据目录。

- **界面**：用 Bash 后台跑 `pnpm dev`（预览面板没有「文稿」权限，自己启动不了），再用 `.claude/launch.json` 的 `ui-mock` 打开 `http://localhost:1420/?mock`（内存里的模拟数据）。仓库里改任何文件（文档也算）页面都会刷新、模拟数据清空，等结果时别动文件。参数：`&notes=prototype` 真实的 179 条笔记；`&vault=new|open`（默认锁着，测试主密码 `mock-master-1`）、`&touch=fail|none`；`&youzi=ready` 一打开就有模拟的本地模型；`&kb=demo` 先放两个知识库（一个扫描件、一个读不了的文件；`knowledge` 测试里有编的没文字 PDF）；`&brief=fail|off` 今日简报（`&mood=calm|busy|good|worry|plain` 换简报的心情，柚子跟着变）；`&year=card` 首页任何一天都显示年度总结卡片；`&site=sandbox|missing|clean|big|ahead` 呦呦漫游（开发版还没副本、找不到文件夹、没有改动、有超大的文件、有没推的提交；commit 文本写「失败测试」「上线失败」得到检查没过 / 上线失败；「作品」里有三篇模拟作品，图片是按网址画的色块）；问题里写「滚动测试」「失败测试」得到长回复 / 失败；柚子提议写数据后，下一句「《X》是Y写的」把前面卡片里那本书的那一条换掉（改卡片；Rust 里是 `a_pending_item_is_replaced_in_its_place`、`a_follow_up_changes_the_earlier_replys_pending_card`，书单检索查到同名别人的书用模型自己的作者是 `a_lookup_of_another_work_leaves_the_models_author`）；`&pub2md=keys` Pub2MD 像正式版那样要填 Mathpix 的 Key，它的「选择文件…」依次拿到一篇论文、「失败测试」（第 3 块出错一次，能「继续」或「删除」）、两张照片、「读书笔记.md」（只翻译），选了先列在「待发送」，点「发送」才开始；柚子选文件第二次多选拿到 xlsx、pptx、png，第一次是 pdf、md；Seeker 有编的资料（林小柚，中文和英文，七个子页都有内容），选文件夹、读模板（英文模板照成稿的样子编的段落）、导出、从 transfer/ 导入都是模拟的（不写文件）；`&youzi=ready` 时柚子的「模板」按钮有置顶模板；想直接看某页用 `/?mock#/finance`。截图常慢一拍，关键结果用 JS 读页面确认（下拉的选项是 `[popover] [data-index]`，模型菜单按服务折叠，先点分组行）；拖拽用 `left_click_drag` 测。
- **速记小窗**：`http://localhost:1420/capture.html?mock` 是它自己的页面（拉到 520 × 292 看）；mock 打开了事件，`window.__TAURI_INTERNALS__.invoke('plugin:event|emit', { event: 'capture-blur' })` 测点别处收起（图钉开着不收），主页面发 `app-menu`（`new-tab`、`close-tab`、`next-tab`、`prev-tab`、`go:0`～`go:8`、`settings`）测菜单的快捷键，发 `capture-chat`（对话编号）、`capture-open`（`{ path, hit }`）测从小窗打开对话和记录。问柚子、翻译加 `&youzi=ready` 才答得出来（窗口变高要在真实窗口里看，浏览器里高度不变）；小窗和主页面的模拟数据各是各的。「存为 .md」在 mock 里只回一个文件名（不写文件），格式转换用 `node --input-type=module -e` 直接调 `src/shared/editor/lite.ts` 的 `liteMarkdown` 看。Rust：`cargo test --manifest-path src-tauri/Cargo.toml capture`（存为 .md：附件复制过去、同名不覆盖、再存一次用回原来的、草稿留着；草稿和附件一起清、失败留草稿、待办默认今天并记住分组、一步撤销不动草稿、清理附件不删草稿里的；小窗的对话不进列表、新的顶掉旧的、继续对话后进「最近」）。⌥Space、盖在全屏 App 上、Esc 回到原来的 App、菜单栏的快捷键只能在打包版真实窗口里试。
- **真实窗口**：新加或改了 Rust 命令的页面，除了 `?mock` 还要在真实窗口里点进去一次（`?mock` 不走 Rust）。`pnpm app:build` 后 `open -n --env POMELO_DATA_DIR=<临时目录> "src-tauri/target/release/bundle/macos/Pomelo OS.app"`，用 `screencapture -x` 截全屏看（我在用别的 App 时，新窗口可能被台前调度缩成左边的缩略图，不是 bug，也别为了截图把它拉到前面；红黄绿的位置按截图量：圆心在 `trafficLightPosition` 的 y − 2 处，按钮之间约 23）；查数据用 `sqlite3` 看临时目录。测完 `pkill -f "target/release/bundle"`（别用 osascript quit，会连正式版一起关）并删掉这个 `.app`。**不要用 osascript 碰 System Events**（会弹「辅助功能」授权框），交互在浏览器里测；要在真实窗口里点，用电脑操作（computer use，会弹授权框由我同意），只授权「Pomelo OS」，点之前确认正式版没在运行。Pomelo 的网页视图在后台点不动，要全屏控制；文字框有焦点时，按下松开没有间隔的点击会被吞掉，按「按下、停 0.15 秒、松开」点。
- **升级测试（装正式版前做）**：先在正式版二进制里 `grep -c -a` 各 migration 的特征 SQL，确定它在哪个版本（不要读真实数据目录；`youzi.db` 的升级脚本也要查）；在临时目录里用 `sqlite3` 依次执行到那个版本的 migration、`PRAGMA user_version=<版本>`、插几条会被新 migration 改动的数据，再用上面的方法打开新打包的 App，检查版本号、`backups/` 里的「升级前」备份和数据。没有新 migration 时（只改了数据文件格式或记录的 JSON 形状）：确认二进制里已有全部 migration，用单元测试读旧形状的记录，再用临时目录打开新 App 确认能启动、版本号不变、数据没被改。
