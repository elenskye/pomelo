- **流畅度**：Pomelo 的窗口是 WebKit，有些东西只在 WebKit 里慢（实时的 SVG 滤镜、整张纸那么大的层被重画），Chrome 和内置浏览器里量不出来。`pnpm dev` 开着时：`node scripts/perf-listen.mjs 1499 <结果.json>` 等结果，再 `open -a Safari "http://localhost:1420/?mock&perf=1499"`（`src/dev/perf.ts`）：页面自己把十个页逐个打开、再在开着的页之间换、每页最长的那块滚一遍，量帧和帧之间的间隔，打出一张表（首帧、最长的一帧和它在第几毫秒、卡掉多少、手画零件用了多久）。Safari 的窗口要在最前面、屏幕没锁，否则不出帧、等不到结果。`&perfcss=<样式>` 先塞一段样式再量，用来对照（比如把某一层藏起来看是不是它慢）。2026-11-09 的数：改之前每开一页有一帧卡 0.8～1 秒（纸纹滤镜），换成平铺的纸纹后最长 150 毫秒。改外框、纸、手画零件、动效后量一遍；一帧超过 100 毫秒就要查。规矩：页面上不放实时的 `feTurbulence` 这类滤镜；整页大小的层不改 `z-index`（WebKit 会整层重画，叠着的页的层级写死在元素上）；给最上面那页开层用 `will-change: opacity`，不用 transform（页面里 `position: fixed` 的东西会跟着它定位）。
- **在 Safari 里遥控**：有些毛病只在 WebKit 里出现，内置浏览器复现不了。`pnpm dev` 开着时 `open -g -a Safari "http://localhost:1420/?mock&drive=1498"`（`-g` 不抢前台），再 `node scripts/drive.mjs 1498 <脚本.js>`：页面（`src/dev/drive.ts`）把脚本当成 async 函数体跑一遍，`return` 的东西打出来；脚本里有 `sleep`、`$`、`$$`、`type(输入框, 字)`、`key(键)`。标签页在后台时动画不走、`requestAnimationFrame` 不跑，只能量排版和状态；要看动画得让 Safari 在最前面。开发版的真窗口也能遥控：`VITE_DRIVE=1498 pnpm app:dev`。靠真的鼠标、键盘焦点才出现的毛病（比如有焦点的输入框滑出窗口，WebKit 把整个窗口的内容滚上去）脚本复现不了，要在打包版的真实窗口里用电脑操作、而且要全屏控制。
