# 数据结构

`pomelo.db` 共 32 张表，当前数据库版本是 22（每个版本改了什么见文末）。小拾的数据在单独的 `picky.db`，见「小拾」一节。规则都在 Rust 里，各模块文件开头有摘要。

## 通用约定

- 每条记录都有 `id`、`created_at`、`updated_at`，下面省略。
- 日期写成 `2026-09-28`，年月 `2026-09`，年 `2026`。选项类字段存英文代码，界面显示中文。
- `sort_order` 是手动排序（越小越靠前），新加的排最后。
- 文字去掉首尾空格，空文字存为「没填」。删除上一级时，下面的东西一起删（另有说明的除外）。

## 状态、类型、设置

书单、影单、绘画课节共用一套状态：

| 代码 | 摸鱼读读 | 好奇看看 | 随意画画 |
|---|---|---|---|
| `unmarked` | 待标记 | 待标记 | 待标记 |
| `todo` | 想读 | 想看 | 未开始 |
| `doing` | 在读 | 在看 | 进行中 |
| `done` | 已读 | 已看 | 已完成 |

- 新建书影默认「待标记」，新建课节默认「未开始」。
- **完成时间**：书影只记年，课节记年月。标为完成时还没填，就自动填今年 / 当月；改回其他状态不清除（课节圆圈上的「取消完成」例外，相当于撤销）。

**kinds**（可以自己增删改的类型）：`module` 属于哪个模块、`name`（同模块不重名，最多 20 字）、`sort_order`。记录里只存 `kind_id`；删类型后记录变「未分类」。各模块：`books`（虚构、非虚构、漫画、其他）、`films`（电影、剧集、动漫）、`drawing`（正课、DLC 跟画、LIVE 辅导）、`packing`（重要物品、随身、护理、兴趣）、`fin_out` 支出分类、`fin_in` 收入分类、`job_channel` 投递渠道。

**settings**：`key`、`value`（JSON）。界面状态，比如 `ui.module_hidden` 隐藏的模块、`ui.module_order` 侧栏顺序、`ui.sidebar_collapsed`。不进撤销。

## 摸鱼读读 · 好奇看看

**books** / **films**（结构相同，作者一栏在影视里叫导演）：`title`（必填）、`author` / `director`（多人用「 / 」隔开）、`country`、`kind_id`、`status`、`rating`（1～5，可不填）、`finished_year`、`note`。

**book_rereads** / **film_rereads**（重读 / 重看，第一次之后的每一次）：`book_id` / `film_id`、`year`、`rating`、`sort_order`。表格的完成时间 = 所有次里最近的一年。

## 随意画画

**drawing_courses**：`name`（不重名）、`note`、`sort_order`。

**drawing_lessons**：`course_id`、`code` 编号（如 `2B`，只用来显示，不用来排序）、`kind_id`、`title`（必填）、`status`、`finished_month`、`note`、`sort_order`。

## 出门走走

**packing_templates**：`name`（不重名）、`note`、`sort_order`。**packing_template_items**：`template_id`、`kind_id` 类别、`name`、`note`、`sort_order`。

**trips**：`name`、`template_id`（只作记录，模板删了出行还在）、`depart_on` 出发日期、`note`。**trip_items**：`trip_id`、`kind_id`、`name`、`note`、`packed` 已装好、`sort_order`。

建出行时从模板或以前的出行复制一份清单（从出行复制时全部变回没装），之后各改各的。

## 一步一步

**todo_groups**：`name`（不重名）、`sort_order`。

**todo_goals**：`group_id`、`name`、`status`（`active` / `paused` / `done`）、`start_date` · `end_date`、`note`、`review` 复盘、`sort_order`。

**todo_tasks**：

| 字段 | 含义 |
|---|---|
| `group_id` · `goal_id` · `parent_id` | 所在分组、目标（可空）、上一层任务（空 = 顶层；子任务跟着顶层任务的分组和目标） |
| `title` · `note` · `link` | 标题、内容（可以 `**加粗**`）、链接 |
| `task_type` | `normal` 普通 / `repeat` 重复 / `checkin` 打卡 / `progress` 进度条 |
| `start_date` · `due_date` | 时间段（开始可空）；重复任务的 `due_date` 是「这一次」，由规则推算 |
| `plan_date` | 重复（完成后）：从哪天开始 |
| `repeat_rule` · `repeat_total` · `done_before` | 重复 / 打卡的规则、一共几次（空 = 不限）、用 Pomelo 前已经做了几次 |
| `target` · `unit` | 进度条的目标数量、单位 |
| `done` · `done_at` · `collapsed` · `sort_order` | 完成、完成时间、子任务折叠、同层顺序 |
| `repeat_until` · `period` | 旧字段，不用 |

**todo_logs**（完成记录）：`task_id`、`day`、`amount`（默认 1）。重复每做完一次、打卡每天、进度条每记一笔各一条。

**重复规则**：`daily`、`weekly:1,2,3,4,5`（周一是 1）、`monthly:1,15`（没有这天用月底）、`yearly:12-31`（`/3` 每 3 年；02-29 平年用 02-28）、`every:3d` / `every:2w`、`after:7d` · `2w` · `6m` · `1y`（完成后过多久）。打卡只能每天或每周几天。

- **勾选**：勾上一个任务，下面的一起勾上；子任务全勾上时上一层自动勾上；取消或新加子任务时上一层自动取消。**进度**只数最底层的任务。
- **今天**：没完成、不在暂停或已完成目标里，截止是今天或更早、或今天在时间段里。
- **重复**：从今天（或开始日期，取晚的）起找第一个该做的日子；做完一次记一条、挪到下一次（一定在这一次和做完那天之后）；次数做满或超过结束日期就整个完成。「跳过这次」只挪日期。已经做了几次 = `done_before` + 记录条数。
- **打卡**：时间段里该打的日子都打了马上完成（没开始日期的从添加那天算），取消一天就变回没完成；补打只能在时间段里、今天以前。时间段结束也自动完成（每天的例行检查）。
- **进度条**：累计达到目标自动完成。

## 钱来钱往

金额都存成「分」的整数（持仓单价除外）。币种 `CNY` / `SGD` / `HKD` / `USD`，从不直接相加，只有总资产按汇率折成人民币。

| 表 | 字段 |
|---|---|
| **fin_accounts** 账户 | `name`（不重名）、`kind`（`bank` / `wallet` / `broker`）、`currency`（记过余额或持仓后不能改）、`closed` 停用、`note`、`sort_order` |
| **fin_balances** 余额 | `account_id`、`day`、`amount`（同账户每天一条；券商账户的余额就是总值） |
| **fin_rates** 汇率 | `day`、`currency`、`rate`（1 单位合多少人民币） |
| **fin_holdings** 持仓 | `account_id`（只能券商）、`day`、`name`、`quantity`（> 0）、`price` 单价（按元存）、`sort_order`；市值 = 数量 × 单价；保存时替换那一天的全部持仓 |
| **fin_entries** 收支 | `flow`（`out` / `in`）、`amount`（> 0）、`currency`、`day`（时间段的第一天）、`end_day`（时间段的最后一天，一天的不填）、`kind_id` 分类、`fixed_id` 由哪个固定支出记的（删固定支出后留着）、`note` |
| **fin_fixed** 固定支出 | `name`（不重名）、`flow`、`amount`、`currency`、`kind_id`、`rule`（`monthly:15` / `yearly:03-01`）、`next_day` 下次哪天记、`stopped`、`note`、`sort_order` |
| **fin_budgets** 预算 | `kind_id` 支出分类、`currency`、`amount` 每月（同分类每币种一条） |

- **总资产**：每个记过余额的日子算一次：各账户到那天为止最近的余额 × 各币种到那天为止最近的汇率。停用的账户过了它最后一次余额就不算。从没填过某币种汇率时，那天不算总数并提示缺什么。
- **时间段**（记小额）：按天平摊；跨月的按天数分到各月（四舍五入到分，加起来正好等于金额）。月合计、报表、预算都这样算；明细里每个跨过的月都列出它。
- **固定支出**：到了 `next_day`（每天的例行检查或刚保存时）就记一笔（备注写名称），挪到下一次；漏掉的几次一起补。
- **预算**：按「分类 + 币种」比当月这个币种的支出。

## 投石问路

**job_statuses**：`name`（不重名）、`stage` 阶段（`wish` 准备 / `applied` 等回音 / `active` 进行中 / `got` 拿到 / `closed` 结束）、`sort_order`。阶段决定规则，但界面不显示、不能改：默认的想投（准备）、已投递（等回音）、网申测评 / 笔试和面试（进行中）、Offer 和已接受（拿到）、被拒（结束）；新加的都是进行中。有投递正处在、或时间线上有它的状态不能删；时间线上有它的不能改成准备；至少留一个。

**jobs**：`company`（必填）、`position`、`location`、`link` JD、`kind_id` 渠道、`resume` 简历位置（家目录里的存成 `~/…`）、`note`、`followed_on` 最近一次「已跟进」。

**job_steps**（每条投递的时间线）：`job_id`、`status_id`（不能是准备阶段；同一条投递不重复）、`done`、`done_on`（勾上那天；勾上了也可以不填）。按状态列表的顺序显示。

- **现在的状态**：最后一个勾上的；一个没勾 = 第一个准备阶段的状态（想投）。投递日期 = 最早勾上的那天。都不存，每次算。
- **新建投递**的时间线默认是除了准备、结束阶段的所有状态，都不勾。
- **该跟进**：现在在等回音阶段，离那一步的日期（或最近一次跟进，取晚的）满 14 天。
- **漏斗**：只看至少勾了一个的投递；等回音、进行中的状态，加上第一个拿到阶段的状态（Offer），各写「勾上的 / 时间线上有它的」。
- **统计**（投出、本周投了、进行中、拿到、漏斗、最近 30 天 / 12 周每天每周投了几份、现在的状态分布）都由 Rust 算（`jobs.rs` 的 `stats`），统计页、首页和小拾用同一份。

## 念念不忘

| 表 | 字段 |
|---|---|
| **notes** | `content` 正文、`pinned` 置顶、`created_at`（精确到毫秒、不重复，导出时靠它认出是哪一条） |
| **note_tags** | `note_id`、`tag` 完整路径（如 `读书/摘抄`）；每次保存都从正文重新提取 |
| **note_refs** 引用 | `note_id` 引用别人的、`ref_id` 被引用的、`sort_order`；任何一边被删引用就没了 |
| **note_tag_meta** 标签设置 | `tag` 完整路径、`pin_order` 置顶先后（只有第一级标签能有）、`icon`（`i:book-open` 这样的是自带线条图标，别的是 emoji，最多 16 个字符） |

- **标签写法**：`#` 在开头或空格后，到空格或下一个 `#`；结尾的 `/` 不算；最多 50 字，不能以 `/` 开头、不能有 `//`。按标签看包括下一级；标签树上的数字含下一级。
- **改名**：把正文里的 `#旧名`（连同 `#旧名/…`）换成新名字、重新提取；标签设置跟着搬（合并时目标自己的图标优先，置顶取早的；改成子标签就不再置顶）。标签的笔记都删光了，设置还留着；两样都空了就删掉那行。
- **置顶的标签**：只列还有笔记用到的第一级标签，按 `pin_order`，各自带着下一级；标签树里不再列它们。
- **正文格式**（只影响显示）：`**加粗**`、`==高亮==`、`++下划线++`、`- ` / `1. ` 列表（每多两个空格深一级）、网址。每一行是一段。
- **置顶笔记**只在没有筛选时排最前；改置顶不更新修改时间。哪天记的按本机时间算。

## 芝麻开门

数据库里只有密文，没有主密码。规则见 `src-tauri/src/modules/vault.rs` 开头，安全设计见[技术架构](architecture.md)。

- **vault_meta**（一行）：从主密码算钥匙的参数（Argon2id 的盐、内存、轮数）、`wrapped_key` 锁起来的「密码库钥匙」、`key_check` 核对钥匙、`master_at` 上次输主密码的时间、`touch_build` · `touch_account` Touch ID 那份钥匙是哪个版本存的、存在钥匙串哪一项、`touch_locked` 要先输主密码。不进撤销。
- **vault_items**：`data`（名称、链接、用户名、账号、密码、备注合在一起，用 XChaCha20-Poly1305 加密）。能撤销。
- 密码库钥匙设置时随机生成，以后不变；改主密码只换锁。Touch ID 那份在钥匙串里（名称「Pomelo OS 芝麻开门」），只认写它的那个版本，所以更新后先输一次主密码。
- 不进数据文件；备份里是密文，恢复到较早的备份后要用那时的主密码。

## 首页

没有自己的表，每次打开由 Rust 现算（`home.rs`），隐藏的模块不算。

- **今年读完 / 看完**：已读 / 已看且完成时间是今年的，加上重读 / 重看里有今年的，一本只算一次。**画完**：已完成、完成时间在今年的课节。**完成**：和「回看」一样，今年勾掉的任务加上今年的每次重复、打卡、进度记录。**笔记**：今年记的。**投出**：投递日期在今年的。
- **总资产**：每个更新日的总数，缺汇率的那天不画。**求职**：本周投了 = 投递日期在本周一以后；进行中 = 现在在「等回音」或「进行中」阶段；拿到 = Offer、已接受；该跟进的按等得久的排前面。
- **最近记录**：各类记录按新加的时间、待办按勾掉的时间，取最近 8 条。书影、课节读完 / 画完没记具体时间，只按新加算；导入的记录按导入的时间算。
- **绘画进度**：有课节、还没全部完成的课程；下一节 = 进行中的那节，没有就是顺序上第一节没完成的。

## 小拾（picky.db）

- 单独一个数据库文件 `picky.db`，和 `pomelo.db` 放在同一个数据文件夹，有自己的升级脚本（`migrations/picky/`）和版本号，当前是版本 6；`pomelo.db` 不因小拾改结构。附件和项目资料的副本放在旁边的 `picky-files/`。
- 表结构沿用原来 Picky 第 5 版（编号改成整数，去掉 Peck 和搜索表）。
- 撤销覆盖小拾的整理操作；发消息、生成回复、建索引、删副本不进撤销。
- 数据文件（导出 / 导入）只带记忆、模板、用途预设、全局指令、项目和背景指令（见文末）；会话和附件用小拾自己的导出。

**preferences**：小拾的设置，`key`、`value`（JSON）。`model.selection` 现在选的模型（`local` 本地，或 `cloud:<id>`）；`memory.enabled` 使用记忆（设置里的总开关，默认开）；`ui.session` 上次打开的对话、`ui.list_collapsed` 对话列表收起没有、`ui.collapsed_projects` 收起的项目、`ui.archive_open` 归档展开没有（界面状态）；`cloud.models` 常用云端模型（名称、服务、接口模型名、上下文、回复上限；第一次打开时放进两个 DeepSeek 默认项，删了不会再加回来）；`data.cloud` 各模块能不能发给云端（只存改过的，没改的用默认：钱来钱往不能，其他能）。不进撤销。API Key 不在这里，只在钥匙串。

**sessions**（对话）：`title`、`title_source`（`auto` 取第一个问题的第一行、最多 40 字，`user` 改过名；改名改成空就回到自动标题）、`active_root_id` 显示的那条路径从哪条消息开始、`project_id` 所属项目、`pinned_at` 置顶的时间、`archived_at` 归档的时间、`sort_order` 在列表里手动排的位置。`updated_at` 是最后一次发消息的时间，改名、置顶、归档、移动、排序都不碰它。
- **在哪个列表**：归档的只在「归档」；置顶的（没归档）只在「置顶」，项目不变；其他的在所属项目，没有项目的在「最近」。
- **顺序**：一个列表没被手动拖过时按最后发消息的时间排；拖过一次就记在 `manual_lists`，之后照手动的顺序，新来的（新对话、移进来的）排在最上面。拖完顺序没变就什么都不记。
- 在归档的对话里发消息，自动恢复。删除对话会一起删掉它的消息和调用记录。这些整理都能 ⌘Z。

**projects**（项目）：`name`（最多 60 字，空的叫「未命名项目」）、`instructions` 背景指令（项目里的对话发给模型时放在最前面）、`sort_order`（新项目排最上面）。删项目不删对话：列在它下面的移到「最近」最上面，置顶、归档的留在原处。

**manual_lists**：手动排过序的列表：`pinned`、`recent`、`archived`、`project:<id>`。

**templates**（模板）：`title`（最多 60 字，空的叫「未命名模板」）、`category`（最多 20 字，空的算「未分类」）、`body` 内容（`{{名称}}` 是待填位置）、`pinned_at` 置顶的时间、`last_used_at` 上次用的时间（只用来排「/」菜单，不进撤销）。列出时置顶的在前（按置顶先后），其余按分类、名称。

**presets**（用途预设）：`name`（必填，最多 30 字）、`content`、`sort_order`（新的排最后）。

**global_instructions**：只有一行，`content` 是全局指令，空的就是没有。

**sessions** 另有 `instructions` 会话指令和 `preset_id` 用途预设（删预设时清空）。
- **指令**：发给模型的系统消息 = 全局、项目、会话、预设四层，各自去掉首尾空白、空的不要，中间空一行。指令预览和真正发送用同一段代码。草稿的会话指令和预设先留在页面上，发第一句时和对话一起保存。

**context_summaries**（上下文摘要）：`through_message_id` 摘要到哪条消息为止、`run_id` 写它的那次调用（`kind = summary`）、`content`。只存写完的摘要；它所到的消息在显示的那条路径上才用（有几条就用最远的），改了或重新生成它前面的消息就不用了，切回来又能用。原来的消息都留着。
- **上下文**：发送时先放系统消息、摘要和新问题，再从最近的消息往前放，放不下的不发；回复留出窗口的 1/4（1024～8192）。窗口用本地服务报的值（没有就用模型清单的），云端用常用模型里的设置，模拟模式 8192。大小优先用本地模型自己数（tokenize），数不了就保守估算（汉字一个算一个，其他三个算一个）。
- **总结**：保留最近两轮（短对话保留一轮）原文，之前的分段读完合进已有的摘要；占用生成的位置，能停止；不进撤销。

**artifacts**（文件副本）：附件和项目资料的每个版本都是一份副本，放在 `picky-files/`（`file_name` 是随机名）。`display_name` 原文件名、`media_type`（文本 / Markdown / PDF）、`byte_count`、`sha256`、`page_count`（PDF）、`text_chars`、`deleted_at`（空间管理删掉了副本，行留着，旧消息能写「文件已删除」）。同样的内容只存一份。
- **能加的文件**：.txt、.md、.pdf，自己选的普通文件（不能是文件夹、替身），最多 200 MB，要有文字（扫描版 PDF 不行）。PDF 用系统自带的 PDFKit 取文字。加文件只是存一份副本，不进撤销。

**artifact_segments**：取出的文字：PDF 每页一段（没字的页跳过），文本按 Markdown 标题分节、每段最多 6000 字。`page_start` / `page_end` / `heading` 用来写「第 3 页」「某一节」。

**message_attachments**：问题带的附件（`position` 顺序）。同一条路径上前面问题的附件，后面提问时还会一起发。

**reading_notes**（阅读要点）：附件和资料放不下时分段阅读，每页 / 每节一条要点，属于那次回复的调用（`kind = reading`），停止了也留着。

**project_files**（项目资料）：`project_id`、`current_version` 现在用哪一版、`indexed` 选了「建立索引」、`sort_order`。**project_file_versions**：每一版对应一份副本。同一个项目里同样的内容不能加两次。「替换为新版本」加一版，删资料不删副本（会出现在附件库）。添加、替换、移除、建立 / 取消索引都能 ⌘Z。

**message_project_files**：问题用了哪些资料、用的是第几版（换了新版本后旧消息还对应旧版本）。

**artifact_indexes / artifact_chunks**（索引）：某个副本按某个向量模型建的索引：约 240 个词一段（句子拼起来，短的末句会在下一段开头再出现一次），带「资料名 · 第 3 页」嵌入，向量是 32 位浮点数。只有「建立索引」的资料的当前版本保留索引。索引是算出来的，不进撤销，随时可以重建；最多 5000 段。
- **检索**：项目里提问时，从当前版本已建好索引的资料里找最相关的至多 6 段（相似度 0.35 以上），这条消息已经全文发送的资料不找。8081 用不了时先问：不检索直接发送、重试或取消。

**run_passages**：一次回复检索到的段落（当时的文字和标签）。

**memories**（记忆）：`content` 一两句话（1～300 字）、`project_id`（空 = 全局）、`enabled`、`local_only` 仅本地（选云端模型时不用）、`source`（`manual` 在管理里加 / `command` 对话里 /记住 / `import` 从用途预设拆分，Picky 里来的）、`source_session_id` 从哪个对话记下的（不设外键，对话删了记忆还在）、`noted_on` 记于哪天（改了文字就记成当天）。新建、修改、开关、删除都能 ⌘Z。删项目时它的记忆留着，改成全局并停用。
- **memory_projects**：项目记忆同时用于的其他项目。**projects.include_global_memories**：项目里的对话也用全局记忆（默认开）。**sessions.memory_disabled**：这个对话关闭记忆。
- **哪些记忆能用**：设置里关了「使用记忆」、这个对话关了、或这一条没勾「本条使用记忆」，就都不用；否则是启用的、在范围内的记忆（不在项目里只用全局的；项目里用本项目的、共享给它的，加上全局的，除非项目关了），选云端模型时去掉仅本地的。预览和发送用同一条规则。
- **挑选**：保存问题前，用 8081 挑出和问题最相关的至多 6 条（相似度 0.35 以上），带「记于」日期放在指令后面；挑不了时先问：不用它们直接发、重试或取消。分段阅读只带指令，不带记忆。

**memory_vectors**：记忆的向量缓存（按向量模型和文字的哈希），算出来的，不进撤销。

**run_memories**：一次回复用到的记忆（当时的文字和日期，记忆改了、删了也不变）。

**messages**：`session_id`、`run_id`、`parent_id` 上一条、`active_child_id` 显示的下一条、`role`（`user` / `assistant`）、`content`、`reasoning` 思考过程（不发回给模型）、`reasoning_ms` 想了多久、`state`（`complete` / `streaming` 正在写 / `cancelled` 停止了 / `failed` / `interrupted` 中断）。
- 同一条消息的几个版本是同一个上一条下面、角色相同的几条；每个版本记得自己的下一条。显示的路径从 `active_root_id` 顺着 `active_child_id` 走；链接坏了就走最新的那条。
- 发一个问题：在路径末尾加上问题和一条空的回复（新对话在同一步建好），回复边写边存（每 0.75 秒一次）。发给模型的是路径上写完的、有内容的消息加上新问题。
- 打开 App 时，上次没写完的回复标成「中断」。

**run_queries**（查了什么，v0.3.5）：一次回复查 Pomelo 数据的每一次，按顺序：`run_id`、`position`、`round` 第几轮、`call_id` · `tool` · `arguments` 模型怎么要的、`module` 查的模块、`label` 「查了」那一行（如「钱来钱往 · 2026 年 9 月支出（42 笔）」）、`state`（`ok` 查到 / `blocked` 隐藏了或这次不能发给云端 / `failed` 没查成 / `unsupported` 这个模型不支持查数据）、`result` 交给模型的原文、`records` 里面列到的记录（模块、种类、编号、标题，以后点开用）。删对话时一起删；发消息、生成回复都不进撤销。
- **查数据的规则**（`picky/data.rs`）：每个模块一个只读查询，算数用各模块自己的函数（和页面一样）；芝麻开门没有查询；侧栏隐藏的模块不提供、来了也拒绝；选云端时不能发给云端的模块回「没有查」，并让回答开头写明「某某不发给云端，这部分没看」。一次回答最多查 4 轮，之后必须回答；查到的内容截短到窗口放得下（每次最多约 3000 token，写明还有几条没列出）。
- **追问**：最近 3 次查过数据的回答，把查到的内容（每次最多约 1500 token）附在当时的问题后面一起发；发之前按现在的模块规则和模型（本地 / 云端）再筛一遍。
- **几个算法**：资产排名 = 各账户、持仓的变化按期末那天的汇率折成人民币比大小；「拖着」= 没有截止日期、加了 14 天以上还没做，「没动的目标」= 进行中、14 天里没有完成任何东西；绘画速度 = 最近 6 个月（含本月）画完的节数 ÷ 6，预计 = 还剩的节数 ÷ 速度向上取整（`drawing.rs` 的 `pace`）；出行可能漏的 = 模板和其他出行里有、这次没有的物品，名称不分大小写和首尾空格，这次用的模板里的排前面（`packing.rs` 的 `maybe_missing`）。

**runs**（每次调用模型）：`session_id`、`kind`（`reply` 回复 / `summary` 总结 / `reading` 分段阅读）、`model`（`local:<key>` / `cloud:<id>`）、`model_name` 当时的模型名、`state`（`running` / `completed` / `cancelled` / `failed` / `interrupted`）、`error` 失败原因、`prompt_tokens` · `completion_tokens` 用量、`started_at` · `ended_at`。每次调用只结束一次。

## 数据文件（导出 / 导入）

JSON，导出和导入用同一种，当前格式版本 11；旧版本的文件都能导入（转换写在 `transfer.rs` 和各模块里）。

| 部分 | 内容 |
|---|---|
| `format` · `formatVersion` · `exportedAt` · `appVersion` | `pomelo-export`、格式版本、导出时间、App 版本 |
| `kinds` | 各模块的类型名称，按顺序 |
| `modules` | `books` · `films`（含 `rereads`）、`drawing`（课程套课节）、`packing`（模板和出行各套物品）、`todo`（分组套目标和任务，任务套子任务和 `logs`）、`finance`（账户套余额和持仓，另有汇率、固定支出、收支、预算）、`jobs`（状态列表和投递，投递套 `steps`）、`notes`（笔记从早到晚，引用写成对方的 `createdAt`；`tags` 是标签设置）、`picky`（小拾：`globalInstructions`、`projects`、`presets`、`templates`、`memories`，记忆用项目名称关联） |

- 记录之间用**名称**关联，不用编号；顺序就是列表顺序；创建、修改时间都带上。
- 导入时文件里有哪个模块就替换哪个（连同它的类型）；没有的不动。任何一条不合格就整个不导入；覆盖前先确认并备份。
- 小拾的部分写进 `picky.db`：全局指令、模板、记忆整个替换；项目和预设按名称更新或新增，其他的留着（会话还在原来的项目里）。版本 10 以前的文件没有这部分。
- 芝麻开门不在数据文件里。
