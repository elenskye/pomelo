## v0.6 · Pub2MD 并入小拾

把 Python 写的 Pub2MD 用 Rust 重做成小拾的助手：PDF、Word、图片经 Mathpix 识别，程序切块、几块同时做；Worker 整理和翻译每块，Supervisor 审定切块、定术语表、排查出错的块、通读、精修。需求见 requirements.md 的「Pub2MD」。

| 阶段 | 做了什么 |
|---|---|
| 1 底座 | Aliyun 直连 Qwen；思考强度（关、低、中、高）；升级前、导入前、恢复前的备份各留 3 份 |
| 2 提取 + 整理 | Pub2MD 页；Mathpix 提取和原页图；切块和 Supervisor 审定；几块同时整理；程序检查和 Supervisor 排查；停止、继续；工作日志 |
| 3 翻译 | 术语表和联网查术语；逐块翻译；不翻的部分；通读；精修；简繁互转；只翻译文本 |
| 4 格式和页面 | 另存为 Word、PDF、LaTeX、HTML（Mathpix 转）；页面里预览；提示词页；翻译检查逐段比对；「翻译」改名 Translator |
| 5 收尾 | 对照旧 Pub2MD 补上多页 TIFF、简繁不动文件名；升级测试；验收清单 |
| 6 测试、修复和优化（进行中） | 我用 test-files 1～4 真测、边看边改；你在正式版里走一两遍；你提的小优化；验收后删旧项目和测试 Key。验收清单都打勾，v0.6 才算完成 |

- **真测**：Key 放在你给的文件里，每轮测之前先说清楚用量，你同意了再测。test-files-1～3（新闻、杂志、繁体中文，2～4 页）用 DeepSeek Flash 做 Worker 时每份 1～3 分钟；开精修要多 6 分钟左右。
- **我自己定的**：Word 文件没有原页图；原页图用系统的 PDFKit 画；设置和最近几次存在 `picky.db` 的偏好里，不加升级脚本；Supervisor 的请求不占 Worker 同时做的名额；精修把整理和翻译各审一次；作者和单位不翻时论文标题照翻；术语表只在英译中时做、思考最多「低」，没做成就不带术语表接着翻；审定切块、通读的思考最多「中」；备用模型只能选云端模型，Worker 和 Supervisor 被内容审核拦下都改用它；每篇文章只有一块时不通读；页图只带这一块占了 300 字以上的页；另存为默认 Word；删除的文档移到废纸篓。
- **新依赖**：简繁转换用 ferrous-opencc 0.4（Apache-2.0）；预览用 mathpix-markdown-it 3.0.1（MIT，只用它的浏览器版，App 大了约 4.8 MB）。
